# CQU 数据准备与 O9 输入协议

本说明覆盖训练前的数据清单、整文件划分和输入预处理。二分类头、短程训练与恢复入口已在第三步实现，接口及使用方式见[训练说明](TRAINING.md)；导入模块不读取数据或启动训练。模型本体见 [O9 说明](../o9/README.md)。

上述二分类入口是简化对照；保留重构、六原型、双分支约束与三个转速域的适配入口见[完整O9训练](FULL_TRAINING.md)。已做短程链路检查，并完成设备1CH2折0的首批四组完整训练；后续实验按用户要求停止，结果与边界见工作日志。

## 已固定的数据范围

[catalog.json](catalog.json) 保存用户确认、已核验的70份文件身份与元数据，包含文件名、原始字节/四通道数值哈希、标签、转速、采集顺序、操作阶段、安装状态、通道映射和单位依据。运行时不依赖其他项目或本机探索目录中的旧清单。新增、缺失或变化的CSV会使准备程序停止，须核实后另立数据版本，不能自动猜测标签。

| 每台设备 | 正常 | 故障 | 合计 | 用途 |
|---|---:|---:|---:|---|
| 主要记录 | 9 | 12 | 21 | 三折开发实验 |
| 历史记录 | 0 | 14 | 14 | 独立批次检查，不参与训练、早停、阈值或权重选择 |

两台主要记录共42份，历史故障共28份。设备1主要故障包含拿掉配重前3份、装回原配重后9份；设备2主要故障包含装回故障轴承后较早3份、随后连续采集9份。每台主要记录的200/600/1000 rpm档位各为正常3份、故障4份。保留较弱或有波动的故障，不按信号强弱挑选记录。400/800 rpm只有历史故障。

标签0为正常，1为该设备对应故障；正常仅指恢复对应人为故障。两台分别建立任务，不能把它们混在一起据此宣称跨设备识别不平衡和外圈故障。设备1装回配重后同档三份是连续采集，不是三次独立重启。设备2正常/故障经历换轴承，仍有安装状态混杂。

## 三折划分

先按整个CSV决定分组，再生成窗口；任何通道、切片、未来增强都继承源文件分组。每台每折如下：

| 集合 | 文件数 | 每个实验的窗口数 | 作用 |
|---|---:|---:|---|
| `train` | 8 | 480 | 拟合模型 |
| `validation` | 6 | 360 | 只在本折内选权重、早停和参数 |
| `test` | 7 | 420 | 本折外层开发评估，不用于选优 |
| `historical` | 14 | 840 | 历史故障批次检查 |

每个集合的主要记录均覆盖三档转速和两个标签。排序键为原CSV采集时间、文件名，不读取信号或成绩：每档正常按顺序编号0/1/2，编号就是外层留出折；故障按顺序编号0/1/2/3，其留出折为“编号加转速档位序号，再除3取余”。这使每折三个转速中的故障留出数为2/1/1，合计正常3、故障4。

去掉外层留出后，在每个“设备、转速、标签”的剩余记录内，以“折编号除剩余数量取余”选1份验证文件；其余用于训练。每份主要记录恰好在一个外层折留出。划分规则无随机数，清单行顺序变化不会改变结果。

所有初始化候选使用同一划分和预处理，在各折自己的验证文件上选择；不能依据外层或历史表现反复调参后仍称其独立评估。整个数据集此前都被探索查看，这只是当前采集内的开发评估，不是最终盲测，也不证明跨日期、重装或重启后有效。历史故障没有匹配正常，不能提供历史正常误报率。

## 首轮预处理

本协议由用户于2026-10-25确认：先实施8192 Hz、4096点方案，沿用逐窗口标准化。保留10 kHz的对照尚未实施。

1. 四通道原值按10 kHz、m/s²解释；即使旧表头写g也不乘除9.80665。核对原始字节及数值哈希，拒绝非有限值、点数变化和不足30.2秒的记录。
2. 对选定通道的整记录去除直流均值，采用`scipy.signal.resample_poly`按512/625重采样，之后恢复均值以保留标准化前统计。抗混叠FIR由`firwin`设计：62501抽头，设计采样率5120000 Hz，截止4096 Hz，Kaiser参数8.6，`scale=True`，`padtype='line'`。明确滤波参数，避免使用默认短滤波器时4.5 kHz抑制不足及直流波纹的问题。
3. 从接近0.1秒处取统一30秒。目标网格四舍五入到第819点，实际起点为0.0999755859375秒；取目标区间`[819,246579)`。先整记录滤波，再裁切，保留首尾余量，不把每个窗口分别滤波。
4. 切成60个4096点、不重叠的0.5秒窗口。不补零、不拉伸、不使用剩余尾段、不做降噪或增强。每个窗口按总体标准差（`ddof=0`）去均值、除以标准差；统计计算用float64，输出float32的`[60,1,4096]`。常量、近常量或非有限窗口直接报错。
5. 保存每个窗口的标准化前均值、标准差、RMS、目标采样点和原采样网格上的小数坐标；另存原始全记录通道幅值统计。滤波使用周边样本，坐标表示时间对齐位置，不表示只依赖一个原始样本区间。

标准化会移除绝对幅值，不能假设故障振动更大就会被当前模型直接利用。重采样会衰减4096 Hz附近及以上内容，之前3000～4500 Hz特征不能原样等同为模型证据。0.5秒在低速下覆盖的转数有限，是否足够需后续训练验证。这些限制适用于从零和旧权重微调两组。

## 文件与公共接口

| 文件 | 接口 | 约定 |
|---|---|---|
| `__init__.py` | 包入口 | 无读取或训练副作用 |
| `catalog.py` | `load_catalog(path=...) -> dict` | 固定70份元数据及范围检查 |
| `catalog.py` | `resolve_cqu_root(data_root=None) -> Path` | 参数优先，其次`CNN_DATA_ROOT`，最后仓库`data/`；均在其下找`CQU/` |
| `catalog.py` | `source_path(record, cqu_root) -> Path`、`sha256_file(path) -> str`、`verify_sources(records, cqu_root) -> dict` | 校验普通源文件路径、字节与完整范围 |
| `catalog.py` | `build_splits(records) -> dict`、`validate_splits(records, splits) -> None` | 生成和验证三折整文件分组；失败抛出`ValueError` |
| `preprocessing.py` | `PROTOCOL`、`read_record(path, record) -> ndarray` | 固定输入协议，读取`[N,4]`的float64原值 |
| `preprocessing.py` | `preprocess_channel(signal) -> (windows, stats)` | 返回`[60,1,4096]`的float32数组与60份逐窗统计 |
| `prepare.py` | `prepare(output, data_root=None) -> dict` | 输出到仓库`tmp/cqu/`的新子目录；不覆盖既有结果，成功返回缓存摘要 |
| `prepare.py` | `iter_partition(prepared_dir, experiment, fold, split)` | 逐窗口迭代，验证缓存哈希；折编号0/1/2，集合为上表四种 |
| `prepare.py` | `write_json(path, value) -> None`、`main() -> None` | 仅新建严格JSON，命令行准备入口 |

`iter_partition`每项包含`x`（`[1,4096]`）、`label`、`record_id`、`channel`、`window_index`、`nominal_motor_rpm`和`sequence_group`。不丢弃小于一批的记录。训练器以后应按`record_id`汇总预测，不能把窗口数当作独立采集数。

原始数据、缓存、测试脚本和验证结果均留在本机忽略目录；功能代码和冻结的正式元数据纳入版本控制。输出包含`catalog.json`、`splits.json`、`protocol.json`、`windows.jsonl`、`arrays/*.npy`、`prepared.json`。70份记录按既定通道合计105份通道缓存、6300个窗口，其中主要3780、历史2520；通道对照没有增加独立文件数。只有全部文件处理及处理后源文件校验成功，才写出`prepared.json`；失败目录保留供检查，重试需用新路径。

## 本地运行

依赖见[requirements.txt](requirements.txt)。本机已存在的cloud虚拟环境可运行，无须安装或升级；这里只调用离线模块，不启动后端。Windows PowerShell，工作目录为仓库根目录`E:/A-codehub/CNN`，示例输出目录须尚不存在：

```powershell
# 启动不读用户配置的子PowerShell，仅在该子进程放行环境激活脚本。
# 点号激活cloud环境；Python的-X utf8启用UTF-8，-m运行数据准备模块，
# --output指定新缓存目录；exit传播Python退出状态。不联网、不需管理员、不安装依赖。
powershell -NoProfile -ExecutionPolicy Bypass -Command '. ./cloud/venv/Scripts/Activate.ps1; python -X utf8 -m training.cqu.prepare --output tmp/cqu/o9_prepare_run01; exit $LASTEXITCODE'
```

预期最后输出`complete: true`、`records: 70`、`record_channels: 105`、`windows: 6300`。需要外置数据时，给模块增加`--data-root`参数，传入包含`CQU/`的目录；该参数只改变只读数据来源，仍须与冻结清单的全部哈希一致。输出不会写入数据目录。

以下Python示例在同一项目虚拟环境、仓库根目录运行；读取已生成的折0训练窗口，不启动训练：

```python
from pathlib import Path
from training.cqu.prepare import iter_partition

first = next(iter_partition(Path("tmp/cqu/o9_prepare_run01"), "device1_ch2", 0, "train"))
assert first["x"].shape == (1, 4096)
```
