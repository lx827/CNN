# 算法模块契约模板

> 复制本模板的结构，不复制占位文字。一个文档覆盖一个算法族或一个稳定数学主题，不对应单个 `.py` 文件。函数签名以源码 docstring 为准。

# `<算法族名称>`

> 状态：当前契约 / 待定稿（注明原因与关联任务）
>
> 实现导航：只写稳定源码目录或 Pipeline 名称，不写逐函数签名。

## 数学目的

说明要估计、变换或判别的物理量，给出理解契约所需的核心公式。长推导放入理论文档并链接。

## 适用与不适用场景

列出转速、负载、信噪比、机械结构、故障形态和采样条件边界。区分“理论上适用”和“本项目已验证”。

## 输入、输出与单位

用表格说明数组维度、采样率、频率/阶次/相位、幅值归一化、物理单位及结构化输出语义。不要把参数表扩写成函数签名镜像。

## 必要前提

说明有限值、最短记录、机械参数、转速来源、频带可分辨性、标定和调用方责任。

## Pipeline 组合

说明上游表示、本模块、下游评估和展示边界的顺序；指出哪些步骤共享结果，哪些步骤不得交换。

## 错误与不可判定语义

区分非法输入、计算失败、有效阴性、不可评估和不可判定。说明 `None`、空结果、状态字段或异常的使用原则；不可判定不得解释为健康。

## 复杂度与内存

给出主要阶数、额外数组、窗口/模态/分段带来的倍率，以及 2G 生产环境下的截断和串行要求。

## 参考文献

列出公式或方法来源；项目内部理论文档与外部文献分开。

## 验证向量与验证状态

列出带解析期望的合成向量、负对照、真实数据集及对应测试入口。明确最近验证日期、实际执行结果或“仅登记测试资产，本次未执行”。文档链接检查不能替代算法正确性验证。
