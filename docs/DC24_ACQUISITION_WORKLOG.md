# DC24 第一版采集工作记录

## 2026-11-05：目标和确认

目标：在CNN中增加真实DC24采集入口，让页面设置时长和采样率、边端执行TCP采集、完整数据上传后端并展示。用户确认原始信号频谱、RMS、包络谱均可选；“包络区间”指用户设置的带通频带上下限。此前已允许短时采集、重连并保留现场参数。不使用子代理。

实现目录为 `CNN`，本地任务分支 `codex/dc24-acquisition-v1`，起点 `b28b85d`。复用同一设备此前在 `D:\打杂目录\回答师兄\dc24-python` 验证的独立驱动与协议；不改训练目录。

## 实现与关键选择

- 新增Vue“真实采集”页与导航、API封装。四通道固定，采样率仅开放已实测的2000/5000 Hz，时长1～60秒，包络频带由用户填写。
- 原驱动移入 `edge/dc24_capture.py`，增加进度/停止回调，保留原配置字节、原始文件及按实际点数控制时长的方式。`dc24_agent.py` 通过现有边端认证接任务、上报状态并上传完整文件。
- 后端新增两张采集表及独立任务接口。完整数据校验后落盘；分析和下载有既有认证。沿用系统线程池，不增加线程池上限。
- FFT、去均值RMS和包络谱用完整记录计算。只对绘图摘要保留极值，原始CSV及分析数组保持完整。
- 数据仍为ADC counts，不擅自转换成加速度。采集页结果留在独立任务记录中，未送入旧机械评分或模型推理，避免把未经物理标定的数据当作有效工程量。
- 历史文件回放为明确标识的可选模式，采样率必须与原文件一致；新入口不修改原有数据集回放。
- 新增 `start_dc24.bat`、操作说明、通俗链路说明与协议文档，更新文档/测试索引。
