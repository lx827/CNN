# ADR 0006：诊断计算库的技术路线与源码构建

- 状态：技术路线与首版平台已确认；配置布局及实现细节讨论中，尚未实现
- 日期：2026-11-12

## 已确认的决策

诊断计算库首个原生候选采用 C++、Eigen 与 pybind11，优先复用第三方数值基座；插值库与线性代数后端分别按语义适配及实际成本选型。首版覆盖 Windows x64、Ubuntu x64 与项目当前 Python 3.13；ARM64 留待后续验证。现有 Rust 边端继续属于设备通信与采集职责。

首版移植保留当前 Python 算法语义，包括极值精化、镜像规则、PCHIP/cubic、SD/Rilling、CEEMDAN 公式及收敛状态，仅接受事先约定的浮点误差。性能移植与算法改进分别验收；具体误差预算尚未确定。

开发机和生产服务器均通过 uv sync 从项目源码按需构建诊断计算扩展，并由构建后端完成编译与安装。用户要求集中根目录配置；根目录统一管理的具体范围、是否保留独立扩展包的构建元数据，以及第三方依赖的源码/二进制来源策略仍需对齐。编译缓存与重建规则尚未确定，不承诺每次同步都无条件重新编译。

## 取舍与验收边界

优先使用现成的数组和数值计算能力，把项目实现集中在算法编排及现有行为的适配。Eigen 不替代插值语义选型，BLAS/LAPACK 后端也不代替极值、边界与筛分规则。库选型不构成性能收益结论。

本决策延续 [ADR 0005](0005-diagnosis-native-benchmark-gate.md) 的固定向量、正确性、状态、所有权和目标资源准入要求。采用源码构建后，目标环境的编译工具链、构建峰值内存及并发限制也需要验证；现有生产分析线程与内存上限继续有效。

## 尚待确定

- 根目录应用配置与独立计算包元数据的归属，以及现有 workspace 的调整方式。
- 首批原生下沉的粒度、插值库候选和浮点误差预算。
- EEMD/CEEMDAN 噪声序列与随机数兼容边界。
- 第三方依赖来源、构建缓存、重建触发及目标 CPU 指令集策略。

当前文档记录已确认的方向，不表示配置迁移、原生实现或生产接入已经完成。后续决定在本 ADR 中继续更新。
