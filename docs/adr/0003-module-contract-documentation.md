# ADR 0003：按稳定模块契约组织文档

- 状态：已接受
- 日期：2026-11-09
- 关联：#70、#80

## 背景

逐 `.py` 文件维护同名 Markdown 曾导致源码、docstring 与镜像文档同时保存函数签名。函数调整或文件移动后，镜像容易保留旧参数、旧返回值和已删除函数；`__init__.md` 又与同级文档重复。文档数量随文件数增长，算法工况、单位和验证状态反而不清晰。

## 决策

采用四层责任边界：

1. **源码 docstring** 是函数签名、参数类型、默认值和实现细节的唯一事实源。
2. **`docs/algorithms/`** 按算法族或机械对象记录稳定契约：数学目的、适用边界、单位、前提、Pipeline、不可判定语义、复杂度、参考文献和验证状态。
3. **`docs/api/`** 记录外部 HTTP/WebSocket 契约；`docs/backend/` 记录业务服务、持久化、缓存、线程和组合关系。
4. **`docs/adr/`** 记录重要决策与替代方案；`docs/tests/` 记录测试分层、运行方式和数据依赖。

`docs/INDEX.md` 只做入口导航。新增、移动、重命名或删除源码文件本身不触发同名文档维护；只有稳定语义、外部契约、模块归属或验证状态变化时才更新对应文档。

历史交接、评估和理论推导可以保留，但必须与当前契约区分。算法切片尚未合并时，可保留明确标记的待定稿语义，不提前声明其为现行 API 或函数契约。

## 替代方案

- **继续逐文件镜像**：导航直接，但持续复制签名且已证明会产生过期内容，拒绝。
- **只保留 docstring**：能消除重复，却无法集中表达跨文件 Pipeline、机械前提和验证证据，拒绝。
- **所有算法集中在一份长文**：减少文件数，但不同算法族互相淹没、修改冲突高，拒绝。

## 后果

- 函数签名不再全量复制到 Markdown；示例只在解释单位或数学语义且不会替代 docstring 时使用。
- 每个公开算法族有唯一权威入口，外部 API 仍以 `docs/api/` 和 OpenAPI 为准。
- 文档同步不能替代正确性测试；文档链接与结构检查只验证文档完整性。
- 删除镜像前需迁移其中有独立价值的工况、单位、不可判定和验证信息。
