# ADR 0004：以类型化证据分离评估状态与诊断结论

- 状态：已采用，随 #77/#84 全栈接入
- 日期：2026-11-11
- 关联：#70、#75、#77、#84

## 背景

旧 `status` 同时表示方法是否可评估和设备是否正常，多个消费者据非 normal 或空值各自推断正常/故障。不同去噪和包络变体还可能将共同信号重复当作独立票。评分、建议、告警、缓存与前端因而分别解释同一原始指标，未知结果可能成为健康 100 或被误判故障。

## 决策

以标准 Evidence → 对象 Evaluation → 总体 Diagnosis 作为唯一业务状态和证据链。公开诊断分开输出 `evaluation_status`、`diagnosis_conclusion`、`health_score` 和对象覆盖范围 `coverage`，不保留长期 `status` 双解释。算法表示自身的计算状态可继续在 analysis 内保留，不能冒充诊断结论。

同源方法按 dependency 传递闭包分组，组内取有限支持而不按方法数量增票；只有独立组进入对象级 normal/anomaly 融合。局部故障命题可共存。评分和建议只消费规范已评估证据，扣分键精确登记、权重只乘一次；结论由有效对象评估产生，不从分数再判一次。

无评估时 unknown/null；一部分对象有效时可以 evaluated/partial，但必须保存其余对象未知与覆盖限制。旧缓存没有完整新证据就要求重新分析，不从旧 status 猜出可信结论。轻摘要、持久化迁移和 HTTP 读写按最终接入实现同步，具体迁移事实见 [持久化契约](../backend/persistence.md)。

复合研究流程保留实际阶段和指标，`research_only` / `production_eligible=false` 在生产证据和存储边界拒绝。研究标签不污染可复用基础算法，也不自动取得独立投票资格。

## 替代方案

- **继续扩大 status 值集合**：仍混合评估成立与诊断结论，消费者无法穷举正确默认行为，拒绝。
- **保留长期双字段兼容并推断旧结论**：使读模型继续双解释，旧未知仍可能被正常默认分支吞掉，拒绝。
- **方法票直接累加或自我组合**：忽略共同观测依赖，增加方法数量即可虚增置信度，拒绝。
- **未知对象一律覆盖总体**：抹掉另一对象合法证据；反过来静默忽略未知也隐瞒覆盖范围，均拒绝。

## 后果与验证边界

API、缓存、后台、告警与前端需要一次性迁移到同一契约；状态变化是明确的外部破坏变更，不偷偷解释成旧正常。前端只保留一个领域状态展示 adapter，未知值中性展示。

业务反例与真实 HTTP/worker 验证保护证据门控、身份、缓存和展示；它们不修改或证明算法数学、健康阈值、真实工况效果或性能。完整规则见 [证据与状态契约](../backend/assessment.md)，研究组合见 [复合流程契约](../algorithms/composite/INDEX.md)。
