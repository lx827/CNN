# ADR 0011：同一应用支持云端与本地工作站

- 状态：已确认，T1～T5 已实施；实机验收状态见实施计划
- 日期：2026-11-15

决策前，`start_dc24.bat` 已在本机启动完整 FastAPI、同一 Vue 构建产物和 DC24 采集进程，但 DC24 采集记录与 `sensor_data → analyzer → diagnosis` 机械诊断链路相互隔离。本地工作站不作为另一套产品实现，也不复用树莓派 Rust 边端充当应用后端。

决定云端与本地工作站共用同一份应用后端、诊断算法、数据库模型、API 和前端。部署配置只负责认证、初始化数据、监听地址和硬件接入等真实差异：本地仅监听 `127.0.0.1`、网页免登录且不创建云端演示设备；云端保留现有认证和初始化行为。两套部署各自拥有数据，不做自动同步。

本地 DC24 原始 counts 文件是波形唯一来源，不再生成本机后端副本或浮点波形副本。统一波形读取边界同时支持云端已有数据库波形和本地文件时间段；读取时在内存转为 float64，直接进入现有诊断入口，不增加全链路归一化。长记录默认按可配置的 5 秒窗口逐段诊断，沿用现有 DataView、Diagnosis、Alarm 和参数查看页面，不另建本地历史页面。

DC24 继续由独立采集进程控制，本机通过回环 HTTP 与应用后端通信。Python TCP、Rust FFI 和原厂 DLL 是同一采集宿主的可选驱动，分别打包并由 uv 依赖组选择；Python/DLL 共用 `FrameProtocolDriver` 的帧协议生命周期，Rust 直接实现最小 `Dc24Driver`，统计能力缺省时省略而不是写恒零。默认使用已实机验证的 Python TCP，Rust Windows 链路单独验收。硬件帧保留四路原始计数，每路可独立启停显示与诊断，一路异常不得阻止其他有效通道分析；首版由用户停用异常通道，不自动判定传感器故障。

本地单次任务与流式任务都只登记现场原件，远程任务保持 ZIP 或逐文件上传。文件批次在现有 DataView 选择新的时间/样本区间与通道集合时创建永久特殊批次，并复用采集登记的批次分配和统一 `process_batch`；无参数重诊保持原批次行为。旧 NULL 采样率只在启动迁移中分别物化显示采样率与诊断覆盖：显示保持 origin/main 的统一配置值，诊断保留设备采样率；无法确定诊断值时以 0 明确标记不可诊断，不在运行时 fallback；0 不阻断显示，只有诊断入口的 `get_diagnosis_sample_rate` 拒绝。

本次不做 counts 工程单位转换、实时示波过程中的连续机械故障评分或本地/云端数据同步。实施顺序与验收边界见[本地工作站实施计划](../本地工作站实施计划.md)。
