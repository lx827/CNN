# ADR 0007：算法模块与内部 C++ 加速接口

- 状态：规则已接受；现有实现尚未按此规则迁移
- 日期：2026-11-12

计算库需要让 EMD、包络、插值和变换等能力独立复用，同时避免经公开接口组合造成重复分配与中间数组。决定将 core 定义为公共基础结构与非算法基础设施，算法按独立数学能力及算法族组织，模块之间通过无环依赖组合；可复用能力不要求已有第二个调用者，也不因公共性就进入 core。

公开 C++ 与 Python 包装可以共用纯 C++ 入口，库内另设专为加速设计的执行接口，接受输出存储、工作区及必要的预计算状态；两类入口复用计算实现。数学能力保持可独立使用，执行允许融合、复用中间结果及省略不需要的结果数组。文件、目录和 CMake target 不要求一一对应。

以输入借用、RAII 拥有结果、显式工作区复用管理内存，按真实状态生命周期引入 Workspace/Plan，不将全部算法对象化。并发由上层调度，每个活跃调用独占可写工作区；Python 的 owner 交接和 GIL 留在绑定层。第一版外部 C++ 使用源码集成，不承诺稳定二进制 ABI。

## 取舍与适用范围

仅有一套易用入口会迫使高频组合调用付出不必要的分配成本；独立维护三套算法实现则导致语义漂移，因此选择两类 C++ 入口共享计算实现。将全部可复用数值算法集中到 core 会模糊模块职责；将每个小步骤都独立建模块也会放大调用复杂度，因此以数学能力和实际组合需要划分。

规则的唯一操作入口是 [cpp-accelerate skill](../../.claude/skills/cpp-accelerate/SKILL.md)。所有权、检查归属、失败状态、线程约束和设计示例在该入口维护，不在本 ADR 复制详细规则。

本决策调整 [ADR 0006](0006-native-diagnosis-compute-package.md) 中后续模块组织的方向；当时插值和求解位于 core、包络位于 emd 的记录仍是实现历史。当前源码布局和已实现范围继续以 [计算库说明](../native_compute.md) 为准。本次仅交付规则与文档，不下沉完整 EMD 家族、不选择 FFT 后端、不调整生产默认后端；这些具体移植工作需独立规格与验证。
