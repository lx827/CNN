# ADR 0010：完整业务 EMD 族与原生随机源

- 状态：已实现，默认 adapter 接入；部署独立执行
- 日期：2026-11-14

原业务默认只把单 IMF 筛分交给 C++，归一化、多模态、随机噪声与集成仍在 Python，难以复用跨成员工作区，EEMD 还保留完整成员池。用户要求完整流程进入 C++ 并由 Python 配置。

决定在既有 `CNN::emd` 中实现独立 `family` 能力，保留仓库 Huang/Wu/Torres 公式、PCHIP/cubic 与 SD/Rilling，不拿 `emd.sift 0.8.1` 的另一套公式替换。公开拥有型入口与内部工作区入口共用计算实现，云端 `NativeEMDImplementation` 通过薄绑定一次调用完整流程；Python 参考仍可显式注入。

随机数改用调用局部 `seed_seq`、`mt19937_64` 和标准库正态分布，Python 只映射任意长度种子。保持相同构建下可复现，放弃旧 NumPy 噪声的逐点序列兼容，以及未验证的跨标准库序列一致性。这使随机生成和成员调度全部在 C++，不需要 Python 回调或整批噪声传入。相同种子重算可能改变 IMF，既有缓存不自动失效；数学质量按模态/状态/独立公式验证，不再用旧噪声逐点数组预算判断随机算法等价。

EEMD 按阶累加，仅保留最终聚合；CEEMDAN 保留白噪声和必要噪声 IMF，筛分/插值工作区跨成员复用。每个活跃调用独占工作区，维持生产两线程池及串行分析。独立 `cnn_compute.emd` 家族与既有 C ABI 保留，未新增全库派发或线程框架。

历史 #106 冻结测量显式固定在旧 Python 外层加原生筛分，不让业务默认切换偷偷改变其噪声与预算。完整原生族使用新端到端测量入口。调用链、内存上界与验证限制见 [完整原生业务 EMD](../algorithms/decomposition/native_business_emd.md)。部署、目标 ECS 全机资源、真实数据效果和 ARM64 均需分别验证；合并本决定不等于已部署。
