# 诊断业务组合全景

> 本文只说明诊断业务如何组合算法、证据和评分。各算法族的数学目的、单位、工况和不可判定语义以 [算法模块索引](algorithms/INDEX.md) 为唯一权威入口；经典公式推导见 [算法原理](算法原理.md)。

## 1. 数据流与责任边界

```text
振动采样与设备配置
  → 业务截断、去趋势和显式去噪
  → 标量/局部/连续转速分析
  → 轴承、齿轮、时域等独立证据
  → 方法级评估与集成投票
  → 统一健康评分、故障标签和建议
  → 持久化、告警与前端展示
```

- 纯数值算法不负责数据库、HTTP、缓存或设备配置。
- 原始/去趋势信号用于转速估计，显式去噪信号用于后续分析；二者不能无条件混用。
- 展示截断发生在完整指标和评估之后。
- 算法失败、未知转速和不可评估不是健康证据。

## 2. 算法族入口

| 子系统 | 稳定契约 | 业务组合注意事项 |
|------|----------|------------------|
| 轴承包络与高级轴承 | [轴承模块](algorithms/bearing/INDEX.md) | 标准 Pipeline 与高级选带/解卷积/循环平稳方法共享明确的证据边界 |
| 齿轮与行星箱 | [齿轮模块](algorithms/gear/INDEX.md) | 定轴和行星运动学、边带间隔及阈值不可混用 |

## 3. 诊断 Engine 编排

Engine 根据已知转频选择恒速路径，未知转频选择自动路径，再将结构化转速结果传给允许该工况的算法。旧 tuple 只承担兼容，不拥有新的数学实现。

快速变速轨迹当前只由阶次分析完整消费。轴承包络、齿轮 TSA 和行星解调收到该工况时明确拒绝按恒速继续；不能先取轨迹中位数再绕过此前提。集成中记录失败方法，同时保留其他合法分支。

详细参数门控和缓存规则见 [诊断编排契约](backend/diagnosis.md)。

## 4. 参数与证据矩阵

| 机械配置 | 可用证据 | 不可得结论 |
|----------|----------|------------|
| 完整轴承几何 | 理论故障频率、谐波、边带与统计证据 | 快速变速下未经补偿的物理频率命中 |
| 完整齿轮参数 | 啮合、边带、TSA 和相应故障指标 | 参数错误时的确定故障位置 |
| 仅一类机械参数 | 该类物理路径和通用时域证据 | 另一类机械对象的物理诊断 |
| 两类均缺 | 时域/频谱/包络等统计异常 | BPFO/BPFI、啮合故障轴等参数化结论 |

配置缺失与配置畸形必须分开：缺失可以走统计路径，畸形需要显式报错。

## 5. Ensemble 策略

Profile 控制计算深度，不改变物理前提：

- `runtime`：后台实时诊断，使用受控方法集合和现有串行/线程限制。
- `balanced`：在响应成本和方法覆盖之间折中。
- `exhaustive`：研究或手动重算，覆盖更多慢方法，仍需受 2G 内存约束。

每个去噪分支共享同一结构化转速分析。轴承、齿轮和时域证据分别形成置信度，再进入综合故障标签、D-S 冲突表示和健康评分。单个方法失败不能被静默删除后宣称“全部方法正常”。

## 6. 健康评分与故障标签

健康分从统一评分源生成，连续扣分用于减少阈值边界的分数突变。评分输入可以包括时域冲击、轴承/齿轮证据、动态基线和融合冲突，但必须遵守各指标自己的门控。

以下概念不可互相替代：

- **方法显著性**：某算法观察到的谱峰或统计证据。
- **投票置信度**：多方法证据的组合强度。
- **故障标签**：当前主导故障类别或未知。
- **健康分**：统一评分模型的综合输出。
- **D-S 冲突**：证据之间的不一致程度，高冲突不应被解释为高置信度。

历史权重和公式推导可查阅 Git 历史；当前维护只保留统一评分源码、模块契约和必要理论，不再复制逐函数参数表。

## 7. 持久化与重新诊断

通道诊断按 `(device, batch, channel, denoise_method)` 读取最新缓存，历史记录不强行合并成唯一数据库行。单批和全设备重新诊断均串行，避免在 2G 服务器并行展开多算法组合。独立阶次查询不创建伪健康诊断，也不覆盖既有通道缓存。

详见 [持久化契约](backend/persistence.md) 和 [后端架构](backend/architecture.md)。
