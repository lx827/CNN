# 树莓派直连配置(MIC-DT-Pi)

记录树莓派连接 Windows 开发机的网络配置(网线直连为主、热点 WiFi 为辅)与排障结论。2026-11-11 首次打通并固化静态 IP;发现过程见文末排障记录。边端部署目标与代码边界见 [Rust 边端 README](../edge/README.md) 与 [Rust 边端工作记录](RUST_EDGE_WORKLOG.md),本页只管"怎么连上它"。

## 速查表

| 项 | 值 |
|----|----|
| 主机名 | `MIC-DT-Pi` |
| 系统 | Debian GNU/Linux 13 (trixie),网络由 NetworkManager 管理 |
| eth0 MAC | `98:fe:54:03:82:b5` |
| wlan0 MAC | `98:fe:54:03:82:b6`(在热点网段定位树莓派靠它,见下文) |
| eth0 地址 | **静态 `192.168.2.100/24`**,DNS `223.5.5.5`;`never-default`(默认路由让给 WiFi),网口现接 DC24 采集卡(`192.168.2.101`) |
| SSH | `ssh nbclass@192.168.2.100`,密码 `666`(sudo 同密码) |
| WiFi | 热点 `acd` / `123456789`,已存为 NetworkManager 连接(autoconnect);地址由热点分配**不固定** |
| 电脑侧 | 以太网口配 `192.168.2.200/24`(下文命令) |

`192.168.2.100` 与 DC24 链路约定一致:边端上位机监听 TCP `6800`,DC24 设备(`192.168.2.101`)主动连入。树莓派顶替此前 Windows 电脑承担的边端角色。

## Windows 侧配置(每次换网口/重置后检查)

电脑以太网口需要与树莓派同网段的地址(管理员 PowerShell):

```powershell
# 查看以太网口当前地址(接口名"以太网")
Get-NetIPAddress -InterfaceAlias "以太网" -AddressFamily IPv4

# 若缺失,添加 192.168.2.200/24
netsh interface ipv4 add address "以太网" 192.168.2.200 255.255.255.0

# 验证(树莓派应答,TTL=64)
ping 192.168.2.100
```

`192.168.2.200` 同时是树莓派的默认网关——树莓派访问外网(如上传云端)需在电脑侧开 ICS/NAT,尚未配置;当前直连仅保证点对点通信。

> 2026-11-11 起:Pi 的网口改接采集卡,`Wired connection 1` 已设 `ipv4.never-default yes`,不再向 `192.168.2.200` 发默认路由,上云走 WiFi 热点。PC 直连场景不受影响(点对点同网段即可)。

## 树莓派侧配置(已固化)

均为 NetworkManager(`Wired connection 1` 为有线连接名):

```bash
# 静态 IP(sudo 密码 666)
sudo nmcli con mod "Wired connection 1" \
  ipv4.method manual \
  ipv4.addresses 192.168.2.100/24 \
  ipv4.gateway 192.168.2.200 \
  ipv4.dns 223.5.5.5
sudo nmcli con up "Wired connection 1"   # 立即生效,SSH 会瞬断

# 热点 WiFi(已配置,记录备查)
sudo nmcli con add type wifi ifname wlan0 con-name acd ssid acd \
  wifi-sec.key-mgmt wpa-psk wifi-sec.psk 123456789

# 核对
nmcli -f ipv4.method,ipv4.addresses,ipv4.gateway con show "Wired connection 1"
ip -4 addr show eth0
```

设备上还留有两个历史热点连接(`iPhone*`),是 2026-11-07 前经手机热点联网的遗留,未删除。

## WiFi 热点场景(拔线后怎么连)

网线拔掉后树莓派自动连 `acd`,`192.168.2.100` 随线失效——热点分配给它的地址**每次可能变**(2026-11-11 实测为 `192.168.97.37`,网段由手机决定),这就是"拔线后 SSH 上不去"的原因。插着线时永远优先用静态地址;两条路径可同时在线。

前提:电脑也连上 `acd`。之后按 **wlan0 MAC `98:fe:54:03:82:b6`**(与 eth0 的 `…b5` 相邻)在热点网段里定位:

```powershell
# 1) 看电脑自己在热点里的网段(如 192.168.97.248/24)
Get-NetIPAddress -InterfaceAlias "WLAN" -AddressFamily IPv4

# 2) 并行 ping 扫该网段,让 ARP 表填充(以 192.168.97 为例,按上一步结果替换)
0..254 | ForEach-Object -Parallel { ping -n 1 -w 200 "192.168.97.$_" > $null } -ThrottleLimit 64

# 3) 按 MAC 找到树莓派当前地址(Windows 的 arp -a 里 MAC 用连字符)
arp -a | Select-String "98-fe-54-03-82-b6"

# 4) 连接(凭据不变)
ssh nbclass@<第 3 步查到的地址>
```

真伪判断老规矩不变:真回应 TTL=64 且 `arp -a` 有真实 MAC;不要用 `MIC-DT-Pi.local`——`.local` 解析会被本机代理 TUN 劫持。

## 排障记录(2026-11-11)

症状:网线直连后,Windows 侧链路 1Gbps Up 但树莓派"零流量、扫遍常见网段无应答、SSH 上不去"。

结论链(按定位顺序):

1. **物理层正常**:`Get-NetAdapterStatistics` 与 pktmon 抓包证明 ARP/mDNS 广播确实发出而收包恒为 0,对端 PHY 活着但网络栈静默。换网线后对端开始发 DHCPDISCOVER——旧线/接触问题是直接诱因之一。
2. **主机名解析被代理劫持**:`MIC-DT-Pi.local` 被本机代理 TUN(Meta Tunnel,fake-IP 网段 `198.18.0.0/15`)解析到 `198.18.0.44`,ping 显示"通"且 TTL=128——**这是代理伪造的回应,不是树莓派**。判断真假:真 Linux 设备 TTL=64,且 `arp -a` 必有对方 MAC。本机开着该代理时,一切 `.local` 解析与部分直连 ping 不可信。
3. **树莓派没有静态 IP,是 DHCP 客户端**:静默期它在等 DHCP 服务器;直连场景下没有服务器,它只周期性广播 DISCOVER。在电脑上跑迷你 DHCP 服务器(见附录)一轮 `DISCOVER→OFFER→REQUEST→ACK` 即拿到地址。
4. **DHCP 服务器必须绑定具体接口地址**:socket 绑 `0.0.0.0` 时,广播 OFFER 被默认路由(metric 0 的代理 TUN)抢走,树莓派收到 12 个 OFFER 全部失踪;改绑 `192.168.2.200` 后立即握手成功。
5. 拿到 IP 后 SSH 凭据:用户名 `nbclass`(出处:`dc24-edge.service` 模板的 `User=nbclass`),密码 `666`。
6. 静态化:按上文 nmcli 命令固化 `192.168.2.100`,此后不再依赖 DHCP。

通用教训:

- 本机代理 TUN 存在时,直连小网段排障要**以 ARP 表真实 MAC 和 pktmon 抓包为准**,ping 文本输出可能被伪造。
- 对"零流量"设备,`Get-NetAdapterStatistics` 的收包计数是第一现场;计数为 0 时任何 IP 扫描都无意义,先解决链路/对端网络栈。
- 树莓派"链路 Up 但完全静默"且灯全亮不闪时,换线、重上电、查供电都值得做;本次换线后即恢复发包。

## 附录:迷你 DHCP 发现脚本

用于给无静态 IP 的设备当场发地址(管理员权限,UDP 67)。关键点:`bind` 必须用**本机该网段的具体地址**,否则广播被默认路由接口(本机为代理 TUN)劫走:

```python
# python -I dhcp_offer.py   (需管理员;网卡须已配 SERVER_IP 同网段地址)
import socket, struct, time

SERVER_IP, OFFER_IP, MAGIC = "192.168.2.200", "192.168.2.50", b"\x63\x82\x53\x63"


def opt(code, data):
    if isinstance(data, int):
        data = bytes([data])
    elif isinstance(data, str):
        data = data.encode()
    return bytes([code, len(data)]) + data


def reply(req, msg_type):
    pkt = bytearray(240)
    pkt[0], pkt[1], pkt[2] = 2, 1, 6  # BOOTREPLY / ethernet / hlen
    pkt[4:8] = req["xid"]
    pkt[16:20] = socket.inet_aton(OFFER_IP)  # yiaddr
    pkt[20:24] = socket.inet_aton(SERVER_IP)  # siaddr
    pkt[28:34] = req["chaddr"]
    pkt[236:240] = MAGIC
    o = opt(53, msg_type) + opt(54, socket.inet_aton(SERVER_IP))
    o += opt(51, struct.pack(">I", 7200)) + opt(1, socket.inet_aton("255.255.255.0"))
    o += opt(3, socket.inet_aton(SERVER_IP)) + opt(6, socket.inet_aton("223.5.5.5"))
    return bytes(pkt) + o + b"\xff"


s = socket.socket(socket.AF_INET, socket.SOCK_DGRAM)
s.setsockopt(socket.SOL_SOCKET, socket.SO_REUSEADDR, 1)
s.setsockopt(socket.SOL_SOCKET, socket.SO_BROADCAST, 1)
s.bind((SERVER_IP, 67))  # 关键:绑具体接口地址
s.settimeout(300)
print("waiting up to 300s ...", flush=True)
while True:
    try:
        data, addr = s.recvfrom(2048)
    except socket.timeout:
        break
    if len(data) < 240 or data[236:240] != MAGIC:
        continue
    req = {"xid": data[4:8], "chaddr": data[28:34]}
    mtype, hostname = (
        data[240 + 2],
        data[data.find(b"\x0c", 240) + 2 : data.find(b"\x0c", 240) + 2 + 20].split(
            b"\x00"
        )[0],
    )
    print(
        f"{mtype} from {':'.join(f'{b:02x}' for b in req['chaddr'])} {hostname!r}",
        flush=True,
    )
    if mtype == 1:
        s.sendto(reply(req, 2), ("255.255.255.255", 68))
    elif mtype == 3:
        s.sendto(reply(req, 5), ("255.255.255.255", 68))
        print("ACK sent", flush=True)
        break
```
