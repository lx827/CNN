# 诊断编排契约

本页描述服务层如何组合算法、参数和评分。数学与单位以 [算法模块索引](../algorithms/INDEX.md) 为准，HTTP 字段以 [API 文档](../api/backend_api.md) 为准。

## Engine 的责任

`DiagnosisEngine` 负责预处理、转速分析、轴承/齿轮方法调度和结果适配，不是第二份算法实现。已知转频走恒速路径，未知转频走自动路径；原始/去趋势信号用于估计，显式去噪信号用于重采样。

旧 tuple 接口只做兼容适配。结构化 `OrderAnalysis` 中的工况是下游前提的依据，不能先摘要成标量再绕过快速变速限制。

## 参数门控

| 配置 | 编排行为 |
|------|----------|
| 仅轴承几何 | 跳过齿轮物理诊断，保留适用的轴承路径 |
| 仅齿轮参数 | 跳过轴承物理诊断，保留适用的齿轮路径 |
| 两者都缺 | 可运行统计异常路径，不匹配理论故障频率 |
| 两者都有 | 分别运行并按证据融合 |

“未配置”与“配置畸形”不同：前者进入无参统计，后者显式报错。无参统计不生成 BPFO/BPFI、啮合频率或故障轴等物理结论。

## 转速工况边界

- 标量恒速和缓变结果可按各算法前提使用。
- 快速变速完整补偿目前只由阶次分析提供；轴承包络、齿轮 TSA 和行星解调收到有效快速变速轨迹时明确拒绝按恒速继续。
- 转速不可判定不是健康，也不得以固定默认值生成正常图或评分。
- 集成中单个方法前提失败应记录该方法错误，不抹掉其他合法方法的结果。

## Ensemble 与评分

`run_research_ensemble` 按 profile 选择去噪、轴承和齿轮方法集合，共享同一结构化转速分析，再汇总时域、轴承和齿轮证据。Profile 是计算深度策略，不改变各算法的物理前提。

健康评分和建议由全项目统一评分/建议模块生成。置信度、故障标签、D-S 冲突和健康分是不同语义：高冲突不能被平均成确定故障，未知输入也不能经零扣分变成健康。

### 连续评分、校准与趋势

连续扣分使用 Sigmoid 平滑阈值过渡：

$$d(v)=d_{max}\frac{1}{1+e^{-(v-v_{th})s}}.$$

多级阶梯若表示“最高级别扣分”，各级贡献采用相邻最大扣分之差并累加，避免简单把每级满分重复相加。评分权重和门控属于统一评分源，不能在前端或单个算法中另算一套健康分。

概率校准只定义从指标到概率的映射；没有独立校准集和可靠性评估时，不能把 Sigmoid 输出解释为实测故障频率。Holt-Winters、Kalman 和线性趋势用于平滑或外推已有序列，不证明机械劣化原因；缺少足够历史基线时必须保留不确定性。

D-S 融合保存各证据的基本概率分配与冲突量。高冲突时可使用 Murphy 平均等工程回退，但结果必须继续暴露冲突，不以组合公式消除语义分歧。

## 缓存与重新诊断

通道诊断缓存以 `(device, batch, channel, denoise_method)` 定位，数据库中保留历史记录并选择最新有效结果。重新诊断按单批或全设备逐批串行执行，不并发覆盖缓存。没有既有批次诊断时，独立阶次查询不创建伪健康记录，也不覆盖通道缓存。

持久化字段和最新记录 tie-break 见 [持久化契约](persistence.md)。
