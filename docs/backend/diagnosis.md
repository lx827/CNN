# 诊断编排契约

> #77/#84 核心、生产后端编排、存储/迁移与 HTTP 已集成开发分支；前端最终收口与集中验证单独记录。外部字段以 [API](../api/backend_api.md) 为准。

## 稳定责任边界

```text
设备/批次/真实通道配置 → 业务窗口与去噪、工况分析
→ 对象 Pipeline 的表示/指标/独立评估
→ Evidence 适配与共同依赖 → 对象 Evaluation
→ 总体 Diagnosis、单次评分/建议 → 缓存/持久化/告警/展示
```

纯算法生成表示，分析 Pipeline 提取指标，诊断 Pipeline 调用分析并评估；业务层只负责策略与副作用。`assess_evidence` 消费规范 Evidence，已有证据可直接重评，不重做分解、FFT、TSA。状态、覆盖、依赖融合、扣分与建议唯一规则见 [证据与状态契约](assessment.md)，不在多个服务复制第二套阈值解释。

## 对象参数与身份

真实通道号来自采样记录，通道缓存身份为 `(device,batch,channel,denoise)`，channel=0 仅为批次摘要；不能用未排序记录枚举序号或第一个有效通道代替。机械配置选该通道，不向其他通道借几何。

| 配置 | 编排行为 |
|------|----------|
| 仅有效轴承几何 | 评估轴承对象；不构造齿轮物理故障 |
| 仅有效定轴/行星模型 | 评估对应齿轮对象；不套默认轴承型号 |
| 对象配置不完整/畸形 | 该对象保留前提原因和 unknown，不能静默落入另一对象 |
| 缺全部物理配置 | 可保留统计表示；不能将缺参或空 Evidence 变成健康正常 |

原始指标、对象局部评估与总体结论分别保存。一个对象未知不抹掉另一有效对象，也不隐瞒未覆盖对象；总体 partial 的含义与 unknown/null 约束按统一状态契约处理。

## 转速与数值前提

原始/去趋势信号用于转速估计，显式去噪信号用于后续故障增强和角域重采样。结构化 OrderAnalysis 保存恒速、逐帧与连续相位工况，不能先缩成标量再绕过物理门控。

- 定轴标准分析使用合法阶次表示，精确 TSA 另需可靠恒速与足够完整转数。
- 标准/高级轴承包络尚未消费快速变速连续相位，不把轨迹中位数当作已补偿恒速。
- 当前行星基础解调与复合 AM/FM/CVS 需要明确恒速及正确参考轴；阶次图有补偿不表示这些下游都支持快速变速。
- 失败/未知转速不默认固定 10 Hz，不生成伪健康谱或正常 Evidence。

数学、单位、频率覆盖与可评估条件见 [算法索引](../algorithms/INDEX.md)。

## 方法编排与依赖

profile 只决定执行矩阵和成本：runtime 使用实际配置去噪与受控方法，balanced/exhaustive 可覆盖更多适用方法。增加去噪或包络变体不会增加独立观测，生产 Evidence 保存共同原始记录依赖，在融合前连通去重。

高级轴承通过族专属 Pipeline：滤波器组/重加权谱峭度、稳定先验 CPW、MED/MCKD、TEO、SC/SCoh。MCKD 无目标实际 MED 回退，证据身份跟随实际方法；SC/SCoh 仍用专属评估，不被包络阈值重算覆盖。

定轴与行星分别有机械模型、边带间隔和基线要求。standard/advanced 对同一行星记录不作为两份独立证据；未校准行星矩、SER 或候选峰不进故障扣分、融合和告警。行星无可比基线为 unknown，而不是正常，也不借定轴阈值。

复合研究流程只展示真实阶段和原始指标，生产适配与存储明确拒绝 `research_only/production_eligible=false`；不是后台 profile 隐式可用方法。公开研究 POST/GET、参数和 JSON 适配见 [API](../api/backend_api.md)。研究 all/ensemble 返回同版本顶层 Domain 与局部结果，不额外嵌套 diagnosis，也不写生产缓存。

## 去噪和方法失败

分解消费者遵守原时间轴、有效区间、选中分量收敛质量。空选择、未收敛、非法频带和异常保留原因；不能吞错返回原信号却声称去噪成功。`DenoisingError` 保存实际方法/原因，直接 HTTP 分析/导出映射结构化 422。

单方法失败由编排保存局部 Evidence 状态并隔离，合法方法可以继续。全部方法失败、空/零数据或没有可评估对象时，统一 unknown/null；不通过另一份规则回退制造成功。算法表示内部计算状态可以保留在 analysis 中，诊断领域只使用两维状态。

## 评分、推荐与告警

assessment 精确消费对象评估的布尔结论，不直接以原始无阈值量重判。共同依赖组最多贡献一次最大加权扣分，冲突系数只乘一次冲突权重。总体结论来自有效对象严重级别，健康分不反向重判状态。

建议保存已评估对象与覆盖限制；告警只消费统一诊断结果和自己的明确策略，不根据未知、null 或非 normal 默认生成故障。设备在线/offline 状态属于运行状态，不替代诊断结论。副作用和轻摘要详见 [业务服务](services.md)、[持久化](persistence.md)。

旧 health_score/health_score_continuous、probability_calibration、recommendation、rule_based、channel_consensus 与旧 fusion/ds_fusion 已删除；评分/建议/依赖融合均收敛到 domain/assessment/adapters/fusion/evidence。旧逐指标告警子模块删除，由统一诊断告警入口消费 Domain。没有为旧 JSON 保留长期双状态解释。历史效果数据保留日期与上下文，不能自动升级成新 Evidence 版本结论。

## 缓存、重新分析与重评

重新分析从原始数据重新运行对象 Pipeline，受 2G 串行约束；直接重评只消费同版本规范 Evidence。两者不是同一个动作，旧载荷缺足够证据时必须重新分析。

通道精确四元键与 channel=0 批次摘要隔离，手动通道分析不覆盖设备/批次摘要，独立阶次转频写回不覆盖通道缓存。直接重评只追加同键新历史行，旧缓存若需重新分析则返回明确冲突提示。具体追加/最新行、迁移与旧缓存拒绝行为见 [持久化契约](persistence.md)；不能用旧 status 猜新评估成立与否。
