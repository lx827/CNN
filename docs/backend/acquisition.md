# DC24 采集服务契约

任务、上传、示波和 WebSocket 的外部字段见 [后端 API](../api/backend_api.md)；采集协议和文件格式见 [DC24 采集说明](../DC24_ACQUISITION.md)。本页只记录云端与本地工作站共用的应用服务语义。

## 原始 counts 显示分析

`services/acquisition_analysis.py` 被整包上传和实时窗口共用，输入为未标定四通道 ADC counts，不修改原始波形，不进入设备故障诊断、健康评分或告警。

- 支持可选 FFT、总体/分段 RMS 和指定频带 Hilbert 包络。
- 频谱与统计在全长数据上计算；绘图摘要在计算后生成。
- 波形与频谱抽点保留极值及真实横坐标，只用于显示。
- 完整 NumPy 分析数组用于 `analysis_arrays.npz`，JSON 摘要用于 `analysis.json`；两者不得因显示点数不同而混淆。
- 包络频带必须满足 `0 < low < high < sample_rate/2`；非法频带明确失败。
- counts 不是加速度等物理标定量，响应与落盘单位必须保留这一事实。
- 分段 RMS 每段独立去均值，末段使用实际长度，时间为段中心秒；通用显示包络不追加轴承诊断低通或故障评估。完整谱长为 `N//2+1`，显示抽点发生在其后。

独立 transforms/statistics 数值路径已随 #76 / PR #81 合并；频谱、分段统计、通用包络和显示抽点的数学语义统一见 [基础数值表示](../algorithms/numeric/INDEX.md)。

## 示波有界内存窗口

`LiveStore` 是线程安全的会话存储，示波样本不写入业务数据库或采样文件，除非用户显式启动“示波中保存”。

- 同一边端同时仅一个活跃会话；已结束会话只保留有界数量。
- 边端帧按序号接收，乱序和重复数据被丢弃。
- 实时窗口最多保留最近 2 秒，并只返回最近**连续**片段；网络缺口两侧不能拼成连续波形。
- RMS 历史、会话数量和内部 chunks 都有界；新帧推进 revision，作为 WS 推送依据。
- 快照排除内部大数组和上传私有状态；路由负责把不存在会话映射为 404。
- 会话状态、保存任务和停止终态由采集生命周期协调，上传完成前不能提前发布停止终态。

## 持久化边界

整包原始文件、可选分析摘要和完整数组属于采集任务产物。远程任务的原始文件落盘根目录由 `ACQUISITION_DATA_DIR` 配置；本地流式任务只在用户选择目录保存一套原件，`finish-stream` 登记其绝对路径，不创建后端副本。数据库任务状态与文件系统产物需要按任务生命周期保持一致。

采集任务保存 `enabled_channels`，有效通道集合由统一配置 `DC24_CHANNELS` 提供，至少选择一路；原始四路文件不随选择改变。完整采集结束后，`services/acquisition_diagnosis.py` 按 `DC24_DIAGNOSIS_WINDOW_SECONDS`（默认 5 秒）划分半开样本区段，末段按实际长度保留，并只为启用通道登记 `sensor_data` 永久特殊批次。`sensor_data.data` 保存文件来源与时间区段，不保存浮点波形，读取契约见 [持久化](persistence.md)。

ZIP 与流式完成入口调用同一个登记函数；批次、来源元数据和任务终态在同一事务提交，完成通知重试与并发完成共用现有分析锁，不重复登记。远程流式完成读取后端上传目录；仅 `DEPLOYMENT_MODE=local` 接受 `local_directory`，校验同一套文件、元数据和 counts 长度后直接登记现场 `counts.i32`。任务下载、任务波形与诊断读取都使用该实际目录，不复制或回退到云端副本。设备身份使用真实 `agent_id`，名称取 agent 状态或该身份，agent 心跳同步设备在线时间。登记后的未分析批次由现有 worker 逐批串行进入 `process_batch`，结果继续由 DataView、Diagnosis、Alarm、Monitor 和设备参数页消费。`analyze_counts` 的显示摘要仍保留，但不代替该机械诊断链路。
