# DC24 四通道采集：第一版操作与实现

本功能在 **CNN 系统仓库**中，入口是导航中的“真实采集”。连接采集器的电脑运行边端，页面下发任务，后端接收完整数据并计算用户选中的分析。训练目录 `wavelet_study_lx827` 继续负责训练。

希望先理解信号怎样变成 CSV，读[采集链路说明](DC24_SIGNAL_TO_CSV.md)；需要重新实现通信，读[协议说明](DC24_PROTOCOL.md)。

## 页面能做什么

| 设置或结果 | 当前行为 |
|---|---|
| 数据来源 | 选择已上线的边端；实时 DC24 与历史文件回放明确标识 |
| 采样率 | 2000 / 5000 Hz，使用两组已实机验证的完整配置 |
| 采集时长 | 1～60 秒；按实际点数达到目标后停止，保留完整帧 |
| 通道 | 固定四路；CH1～CH4 对应原厂软件 6-1～6-4 |
| 原始信号频谱 | 可选，完整记录去均值后加 Hann 窗，输出单边幅值谱 |
| RMS | 可选，输出完整记录去均值 RMS，以及按一秒分段的变化曲线；末段按实际长度 |
| 包络谱 | 可选，用户填写带通下限/上限；四阶 Butterworth、双向滤波、Hilbert 包络，再去均值计算频谱 |
| 包络频带 | `0 < 下限 < 上限 < 采样率/2`，不替用户选择频带 |
| 停止与记录 | 等边端发送停止并保存已采数据；可下载已上传的部分记录 |
| 波形 | 可选通道与时间区间，最多一次查看五秒原始分辨率数据 |
| 文件 | 原始 CSV、采集元数据；选了分析时提供完整分析数组 NPZ |

三项分析可全部取消，仍保存四路原始数据和波形。CSV 始终是有符号 24 位 ADC 原始计数，时间为样本序号除以采样率。图表纵轴使用 counts；物理单位需另行明确传感器标定。这里产生的任务暂不进入旧系统的自动故障评分或 CNN 推理。

5000 Hz、60 秒要求至少每路 300000 点。一帧每路 254 点，因此常见最少记录为 300228 点、60.0456 秒；停止应答前可能再收到完整帧。元数据保留请求时长和实际时长。

## 本机运行

以下均在 **Windows 本机**执行，无需管理员权限，不安装依赖。前提是现有 cloud/edge 虚拟环境与前端依赖已就绪。后端与边端沿用已有 `EDGE_API_KEY` 配置约定；如自定义，两侧必须相同。页面沿用现有登录认证。

### 1. 硬件准备

电脑有线 IP 为 `192.168.2.100/24`，设备为 `192.168.2.101`。原厂软件先脱机，释放电脑 TCP 6800。DC24 会主动连接电脑；仅在任务开始后边端才监听该端口。

边端需同时能访问后端：设备走有线网，远端后端可走电脑现有互联网连接。第一次本机测试建议把三个部分都指向同一台电脑，避免误用未更新的远端 API。

### 2. 启动本机后端

在 PowerShell 窗口一执行。下面的后端会初始化或迁移**本机** `cloud/turbine.db`，原始采集文件默认保存到仓库 `data/acquisitions/`；不修改远端数据库。

```powershell
# 切换到本机CNN后端目录；使现有.env与SQLite相对路径按原约定加载。
Set-Location E:\A-codehub\CNN\cloud
# 激活已有云端虚拟环境，仅影响当前终端，不安装软件。
& .\venv\Scripts\Activate.ps1
# 启动完整后端；--host限制本机访问，--port指定8000端口；Ctrl+C停止。
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

如果本机 cloud 配置过外部数据库，应先确认其目标，不能把上面“本机 SQLite”的说明套用于自定义数据库配置。

### 3. 启动前端

PowerShell 窗口二执行，工作目录为本机前端。临时环境变量仅影响该窗口启动的 Vite，不修改项目代理文件。

```powershell
# 切换到本机CNN前端目录。
Set-Location E:\A-codehub\CNN\wind-turbine-diagnosis
# 指定本次页面访问本机后端；只设置当前终端的进程环境变量。
$env:VITE_BACKEND_BASE_URL='http://127.0.0.1:8000'
# 启动已有Vite开发服务；按终端显示的本机地址打开网页，Ctrl+C停止。
npm run dev
```

若以前在该浏览器设置过“后端地址”，浏览器保存的地址优先于此环境变量，需在原来的配置入口改回本机地址。登录后进入“真实采集”，通常为 `http://127.0.0.1:3000/#/acquisition`。

### 4. 启动连接硬件的边端

PowerShell 窗口三执行。它会向指定后端发送心跳并领取任务，实际采集时才连接硬件、创建文件；Ctrl+C 停止进程。需要现场网线可用，本机模式无须访问互联网。

```powershell
# 切换到本机CNN根目录。
Set-Location E:\A-codehub\CNN
# 激活已有边端虚拟环境，不安装依赖。
& .\edge\venv\Scripts\Activate.ps1
# --cloud指定本机后端根地址，保持窗口运行并等待页面下发任务。
python edge/dc24_agent.py --cloud http://127.0.0.1:8000
```

也可在本机 Windows cmd 的 CNN 根目录运行这一条；`start_dc24.bat` 激活边端环境并启动同一个程序，参数为后端根地址。它只启动边端，前后端仍按上面步骤启动。

```bat
:: 连接本机已启动的后端，等待页面下发DC24任务；不启动旧数据集回放。
start_dc24.bat http://127.0.0.1:8000
```

### 5. 页面操作

1. 选择刚出现的在线边端，确认来源为“DC24 实时采集”。边端在线只代表程序能联系后端，硬件连接要等任务开始后确认。
2. 设置时长、采样率及分析开关。选择包络谱后，填入自己要观察的频带。
3. 开始采集，依次查看等待设备、配置、采集、上传、分析和完成状态。
4. 完成后选择通道与波形区间，下载原始 CSV、元数据或分析数组。

页面提交任务、查看记录、下载数据都会访问所选后端；实际部署到远端后，完整原始数据也会上传远端。本次开发没有部署服务器。

## 数据和实现放在哪里

```text
浏览器 Acquisition.vue
    → POST /api/acquisition/jobs
CNN 后端存任务，边端通过心跳/轮询领取
    → dc24_agent.py 调用 dc24_capture.py
电脑监听6800，向DC24发配置/开始/停止命令
    → samples.csv + metadata.json + rx_stream.bin + commands.jsonl
边端把完整文件打包上传
    → 后端检查时间轴、四通道计数、点数、帧缺口
可选分析读取完整记录
    → 页面摘要图、原始区间、CSV和完整分析数组下载
```

| 位置 | 用途 |
|---|---|
| `edge/dc24_capture.py` | 设备 TCP 协议、拆帧、四通道解析、开始/停止；可独立运行 |
| `edge/dc24_agent.py` | 接任务、上报状态、调用驱动、上传；`--replay-dir` 可显式回放完整记录 |
| `cloud/app/api/acquisition.py` | `/api/acquisition` 任务、边端、上传、下载及原始区间接口 |
| `cloud/app/services/acquisition_analysis.py` | FFT、去均值 RMS、包络谱，完整记录计算 |
| `cloud/app/models.py` | 新增 `acquisition_agents` 和 `acquisition_jobs` 两张表 |
| `wind-turbine-diagnosis/src/views/Acquisition.vue` | 参数、状态、下载、四通道结果及最近任务 |
| `tmp/dc24_acquisition/recordings/<任务ID>/` | 边端默认原始文件目录，Git 忽略 |
| `data/acquisitions/<任务ID>/` | 后端默认接收/分析目录；可用 `ACQUISITION_DATA_DIR` 更换，Git 忽略 |

归档使用 ZIP 无损压缩，上传不会抽点。长图只为显示保留极值；分析使用完整记录。`analysis_arrays.npz` 包含各通道完整频率/幅值数组与所选 RMS 曲线，可用 NumPy `load(..., allow_pickle=False)` 读取。

## 验证范围与已知限制

- 本机真实设备联调：5000 Hz、2 秒任务，四通道各 10160 点，无序号缺口。边端与后端下载的四个输入文件逐字节相同；原始区间逐点一致，全记录 RMS 复算一致，完整 FFT 数组长度正确。
- 实机停止联调：通过HTTP停止正在采集的任务，四路各14732点保留、CSV下载一致。历史回放联调：保留5000 Hz及四路各5080点，数值与源记录前段一致，来源标识为回放。
- 自动化覆盖：两组采样配置、TCP 半包、符号数值、停止保留数据、帧缺口报错、认证、任务校验、完整传输、FFT/RMS/包络数学结果、前端参数及异步生命周期。详见[工作记录](DC24_ACQUISITION_WORKLOG.md)。
- 当前最多一分钟、固定四通道；不是持续运行或断点续采方案。上传失败会保留边端文件并有限重试；进程崩溃后尚无自动任务恢复。
- 停止命令要靠边端收到请求后执行。边端掉线时，页面只能显示请求已提交，不能保证硬件已经停止；驱动异常时会尝试发送 B8 并保留已有文件。
- 包络谱不自动选带，也不更改硬件模拟滤波参数；软件频带不能突破硬件输入链路的有效带宽。两组协议配置保留原厂完整字节，未确认字段没有重新命名或猜测。
- 远端 API、生产部署及公网链路未验证。原厂同段逐点对照属于此前独立驱动阶段的证据，见协议第9节；本次新增验证侧重边端、后端和页面数据接口。
- 页面构建和 Vue 状态测试通过；浏览器自动截图启动被执行策略拒绝，未完成实际浏览器像素及移动端视觉验收。
