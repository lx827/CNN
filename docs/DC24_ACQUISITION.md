# DC24 现场操作：一键启动、实时示波和保存

本功能在 **CNN系统仓库**，不在训练目录。原理见[从传感器到CSV](DC24_SIGNAL_TO_CSV.md)，通信字节格式见[协议说明](DC24_PROTOCOL.md)，修改与验证过程见[工作记录](DC24_ACQUISITION_WORKLOG.md)。

## 到现场后怎么用

1. 网线与传感器接好，电脑有线 IP 保持 `192.168.2.100/24`。如果原厂软件正在运行，请退出以释放 TCP 6800。
2. 双击仓库根目录 **`start_dc24.bat`**。它启动本机后端、提供前端页面、启动真实DC24边端，并打开浏览器；本地工作站页面无需登录。
3. 进入“真实采集”，选择采样率，点击**示波**。四路实时画面开始更新，此时不创建采样文件。
4. 勾选想看的原始信号、原始信号频谱、RMS/均值或包络谱；示波期间也能切换。包络谱需要自己填写带通频带。
5. 填时长、选现场电脑保存目录，并勾选至少一路**诊断通道**，再点击**开始采集**。从下一完整帧开始保存，示波画面继续更新；原始文件仍保存四路。也可以不预先示波，直接点开始采集。
6. 定时结束或点击**停止保存**后，现场原件已经保留，示波继续；后端按默认 5 秒窗口自动登记并串行诊断，可在现有数据查看、诊断、告警、监测和参数页面查看。需要结束硬件连接时，再点**停止示波**。

当前独立程序采用2026-11-06用户确认有效的四路 **IEPE / AC0.2Hz / PASS** 输入配置，页面默认 **10000Hz**。原厂软件与独立程序各自下发配置；只在原厂里修改选项，不会自动更新独立程序。每次连接时独立程序会发送自己的配置，页面显示当前模板，记录中保存实际B2/B5负载。旧输入模板的边端会被拒绝开始新版示波，应重启新版边端。

Windows 边端在环境变量或本机 `collector/.env` 中用 `DC24_DRIVER=python`、`rust` 或 `vendor` 显式选择驱动，环境变量优先。`vendor` 还需将 `DC24_VENDOR_ROOT` 设为包含 `dll/JMServer.dll` 的原厂软件安装目录绝对路径，例如 `D:/VALENIAN动态采集分析软件`。只有点击示波时，DLL 驱动才启动一个 32 位子进程加载已验证版本。设备配置、开始停止、保存和页面操作始终由 CNN 共用宿主控制；指定 DLL 与已验证版本不符时会明确报错。未设置 `DC24_DRIVER` 时仅保留旧默认规则：有原厂目录则使用 DLL，否则使用 Python TCP。

切换采集模块后应退出旧启动窗口，再双击一键启动。启动器检查边端上报的模块，避免把已运行的另一种连接方式当成新配置继续使用，也不会在缺包时静默换成其他驱动。该设置只影响真实采集页的示波和保存。最小安装按选择执行 `uv sync --no-default-groups --group local --group dc24-python`、`... --group dc24-rust` 或 `... --group dc24-vendor`；DLL 适配包不会安装原厂软件。`start_dc24.bat` 使用 `uv run --no-sync`，保留已选环境；缺少所选包时会给出对应的完整安装命令。

也可只用一行。在**本机Windows PowerShell，任意工作目录**执行，无需管理员权限；已有依赖就绪时不访问互联网、不安装软件：

```powershell
# 调用本机CNN启动器；启动本机前后端及硬件边端，打开浏览器，保持终端运行。
& "E:\A-codehub\CNN\start_dc24.bat"
```

启动器不自动开始采样。前端已构建时直接复用；源码更新后只构建一次，不再每次启动Vite开发服务。首次服务实测启动约8秒，已有同版服务复用实测约0.1秒；这不包括首次构建与设备稍后建立连接的等待。

关闭时先在页面停止保存/示波，再在启动器窗口按Ctrl+C。启动器也会尝试先让设备停止和完成保存，再清理本次创建的进程；复用的已有服务不会被它删除或结束。所有原始文件保留。

## 两个操作怎样配合

| 操作 | 设备是否采样 | 页面是否更新 | 是否保存四路采样文件 |
|---|---|---|---|
| 未开始 | 否 | 空白等待 | 否 |
| 示波 | 是 | 是 | 否，仅有界内存窗口 |
| 开始采集 | 是 | 是 | 是，从点击后的下一完整帧开始 |
| 停止保存/定时结束 | 继续示波 | 是 | 文件收尾，之后数据不再写入该记录 |
| 停止示波 | 发B8并等待应答 | 最后画面冻结并标记停止 | 正在保存时先收尾已有文件 |

浏览器刷新或重新进入页面会重新关联该边端正在运行的示波会话，不会自动把历史回放画成实时信号。后端重启会丢失示波内存窗口；已保存文件和数据库任务保留，暂不自动恢复中断的采集。

## 可以设置的内容

| 项目 | 当前规则 |
|---|---|
| 采样率 | 原厂完整档位：50、100、200、500、1000、2000、4000、5000、10000、20000、50000、100000 Hz，每通道 |
| 输入配置 | 固定四路IEPE、AC0.2Hz、PASS；按用户确认有效的原厂新配置同步，当前页面不提供切回电压模式 |
| 时长 | 自填正整数秒，没有上一版60秒上限；或勾选手动结束，后台用0表示手动模式 |
| 通道 | 原始帧固定四路，CH1～CH4对应原厂软件6-1～6-4；每次采集可启用其中至少一路进入诊断，有效集合由后端 capabilities 提供；BNC物理测点对应仍需逐路响应确认 |
| 自动诊断窗口 | `server/.env` 的 `DC24_DIAGNOSIS_WINDOW_SECONDS`，默认 5 秒；末段按实际样本长度分析 |
| 有效通道集合 | `server/.env` 的 `DC24_CHANNELS`，默认 `1,2,3,4`；页面不自行写死 |
| 原始波形 | 四路并排显示；时间窗可选0.01～2秒，保持真实样本时间与数值，不使用平滑曲线拟合 |
| 原始频谱 | 可选；对最近连续窗口去均值、加Hann窗、计算单边幅值谱 |
| RMS/均值 | 可选；显示窗口算术均值、去均值RMS及最近统计趋势，表格保留5位小数；原始计数仍为整数 |
| 包络谱 | 可选；四阶Butterworth带通、双向滤波、Hilbert包络，再去均值计算频谱 |
| 包络区间 | `0 < 下限 < 上限 < 采样率/2`；用户填写，不自动猜选 |
| 保存目录 | 现场电脑绝对路径，可输入，也可点“选择目录…”在现场电脑弹出系统目录选择器 |

用户确认只开放原厂支持的档位。非标准值不能随意标注成实际采样率：实测向设备写6000时收到约6250点/秒。该值不作为页面选项，也不把请求值用于伪造时间轴。

时长按实际样本数和完整帧收尾，例如5000Hz、60秒常见至少300228点/通道、60.0456秒。高采样率的帧更大，不能固定假设每帧254点。元数据记录每路实际点数、实际时长、首尾设备帧序号。

## 图上是什么，文件里是什么

实时图分析**最近连续两秒以内的窗口**，并标出窗口起止时间。波形显示其中用户选择的较短区间；长图只为显示保留极值。图上的FFT和RMS不是整段长记录的全局统计。采集完成后示波仍在继续，图也继续变化；不会用最后的图冒充整份文件。

完整文件保存每一个采样点，不抽点、不用显示图替代CSV。纵轴保持有符号24位ADC **counts**，没有擅自换成加速度。当前输入配置已对齐用户确认有效的IEPE/PASS组合；工程单位标定仍没有自动套用，不能仅因“采到数据”就判断机械正常或故障。

此前规律50Hz信号的数字确实来自设备，但独立程序沿用了早期电压输入模板。用户在原厂改为IEPE/AC0.2Hz/PASS后取得有效对照；重新抓包确认新B2/B5与旧模板不同，现已更新。新版10000Hz网页实测保存3.048秒、30480点/通道，CSV与原始报文逐点一致，四路不再几乎重合。小数位只影响显示，汉宁窗只用于频谱；两者没有用于改写原始波形。

## 文件保存在哪里

本地工作站单次和流式采集都只有**现场原件**一份，位于用户选择目录的任务子目录；远程云端任务保留后端副本。本地单次任务通过 `/upload?local_directory=...` 登记，不再打包 ZIP；远程单次 ZIP 和独立 CLI 保持各自既有保存方式。

| 文件位置 | 默认目录 | 能否选择 |
|---|---|---|
| 本地流式原件 | 一键入口默认 `CNN/data/dc24_recordings/<任务ID>/` | 页面可选任意有写权限的现场绝对目录；任务下载、波形和诊断都读取这里 |
| 远程后端副本 | `CNN/data/acquisitions/<任务ID>/` | 可通过后端环境变量 `ACQUISITION_DATA_DIR` 配置；不用于本地单次或流式原件 |
| 运行/验证日志 | `CNN/tmp/dc24_live/` | Git忽略，不当作训练数据 |

每份采集包含：

- `samples.csv`：`sample_index,time_s,ch0_counts,ch1_counts,ch2_counts,ch3_counts`，时间从本次保存首点开始。
- `metadata.json`：实际点数、时长、采样率、来源、现场路径、首尾帧号、与示波会话样本轴的对应关系等。`transport` 记录本次示波使用的模块，`jmserver` 表示原厂 DLL，`python_tcp` 表示 Python TCP，`rust_tcp` 表示 Rust FFI。
- `rx_stream.bin`：本次保存样本对应的完整设备协议帧；不含点击保存前的示波样本。
- `commands.jsonl`：建立本次会话时的控制命令记录。
- `counts.i32`：四路交错小端int32计数，便于长文件按需读取；不是新采样源。

示波本身不会创建上述采样文件。远程上传以逐文件流式传输，避免上一版32MB ZIP和一次性读取整份长记录的限制；本地流式模式不 PUT 这些文件，关闭文件后仅通过 `finish-stream` 登记实际目录。本地单次 record 未生成 `counts.i32` 时，本机后端通过 `/upload?local_directory=...` 校验 CSV 后在同一现场目录生成，不上传后端副本。后端按需用内存映射读取原始波形，不会把整小时记录一次塞进内存。移动或删除本地原件后，对应下载、波形和诊断批次会失去数据源，不会改用另一份副本。磁盘空间、系统文件大小和远程网络仍是实际约束；传输或登记失败时现场原件保留。

旧版已保存的CSV/NPZ任务接口仍保留。新版实时图使用滑动窗口；采集完成后原始 counts 按窗口进入现有机械诊断，但不自动进行工程单位换算，是否可评估由设备机械参数与各算法前提决定。通道启停同时控制实时显示与诊断，原始帧始终四路。现有 DataView 可对文件批次选择其他时间/样本区间及 CH1～CH4 通道集合，创建新的特殊批次并重新诊断，可重新启用原任务未选通道；原批次和原始文件不变。显示用的 `analyze_counts` 摘要继续保留，不代替机械诊断或告警。

## 程序分工

| 文件 | 职责 |
|---|---|
| `start_dc24.bat`、`scripts/dc24_start.py` | 检查本机环境、必要时构建前端、启动/复用后端和边端、打开页面及清理自有进程 |
| `collector/drivers/dc24/src/dc24_driver/dc24_profiles.json` | 原厂12档完整B5命令负载，云端与现场工具共用 |
| `collector/drivers/dc24/src/dc24_driver/` | 公共窄驱动接口、四路 int32 样本块、帧序号、事件、链路状态与协议实现 |
| `collector/drivers/dc24-python/` | 默认纯 Python TCP 连接适配器 |
| `collector/drivers/dc24-rust/` | 复用 `dc24_edge_core` 的 Rust FFI 薄适配器，携带原生库 |
| `collector/drivers/dc24-vendor/` | 验证本机 DLL、管理 32 位连接进程并交付完整设备帧；不捆绑原厂软件 |
| `collector/dc24_capture.py` | 单次采集宿主；按所选驱动编排配置、进度、停止与原始文件 |
| `collector/dc24_live.py` | 连续示波、有界窗口、从点击时刻保存、远程异步传输或本地原件登记 |
| `collector/dc24_agent.py` | 心跳、会话/任务控制、现场目录选择与认证；继承显式驱动和本地部署配置 |
| `server/app/api/acquisition_live.py` | 实时会话、内存窗口、远程逐文件上传与本地/远程保存完成接口 |
| `server/app/services/acquisition_live.py` | 有界缓存、连续片段和统计趋势 |
| `web/src/views/Acquisition.vue` | 四通道实时示波、显示开关、时长/频带/目录和保存状态 |

## 验证和仍需现场确认的部分

实机4000、20000、100000Hz均已验证“示波不落采样文件 → 示波中保存2秒到选定目录 → 保存后继续示波 → 停止”。每路分别保存8128、40640、201168点；页面实时点与对应文件区间一致，CSV与原始协议帧独立解码逐点一致。这些历史实机结果来自当时逐文件上传链路，不冒充本轮本地单副本登记的实机验收。

原厂12档配置已被动观察。自动测试覆盖源类型隔离、长时长参数、显示开关、变长帧、负数、保存起点、远程流式文件、本地免 PUT 原件登记、任务下载/波形/诊断原件路径、完成幂等、内存上限、缺口不拼接、上传或登记后再发布停止状态及Vue卸载。详细结果与限制见工作记录。

传感器工程单位的独立标定、远端部署、公网带宽、连续数小时稳定性、后台崩溃自动恢复和移动端浏览器像素尚未完成验证。本轮未连接真实 DC24 验证本地单副本链路，Rust Windows 实机采集、停止、保存与诊断也未验收。原始数据和现场配置始终保留。
