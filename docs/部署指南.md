# 部署指南（本地 + 阿里云 ECS）

> 风机齿轮箱智能故障诊断系统的部署与更新。
> 云端运行在阿里云 ECS（Ubuntu 22.04，2核2G），systemd + uv 管理，**不上 Docker**（[ADR-0002](adr/0002-edge-crossbuild-cloud-systemd.md)）。

---

## 部署总则（先读）

1. **uv-only（铁律）**：Python 环境全程由 [uv](https://docs.astral.sh/uv/) 管理。依赖唯一事实源是仓库根 `uv.lock`，安装只经 `uv sync`（服务器用 `uv sync --frozen`，严格按锁文件）；**禁用 pip、conda、手工创建/激活 venv**（[ADR-0001](adr/0001-uv-workspace-python-313.md)）。Python 版本锁定 3.13（`.python-version`），由 uv 自动下载托管，不依赖系统 Python。
2. **云端不上 Docker**：ECS 上只有这一套服务，容器化收益不抵额外复杂度（ADR-0002）。`deploy/edge/` 下的容器只用于 Rust 边端交叉编译构建，与云端部署无关。
3. **2G 内存红线**：ECS 为 2核2G。应用层已内置三重约束——线程池 `max_workers=2`、后台分析 `ANALYSIS_SEM` 串行、DataView 实时计算 5 秒截断（AGENTS.md §5）。任何部署/运维操作都不得引入新并发。
4. workspace 布局：根 `pyproject.toml` 定义 uv workspace（成员 `cloud`、`dc24`），环境建在**仓库根 `.venv/`**，不是 `cloud/venv`。

## 一、本地运行（Windows）

### 1.1 安装工具（一次性）

- **uv**（PowerShell）：

  ```powershell
  powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
  ```

- **Node.js ≥ 18**（仅前端构建需要）：<https://nodejs.org/>

### 1.2 初始化与启动后端

```bash
cd /d/code/CNN          # 仓库根
uv sync                 # 创建根 .venv 并按 uv.lock 安装全部成员(cloud + dc24)

cd cloud
uv run python -m app.main   # 后端 http://localhost:8000，API 文档 /docs
```

> SQLite 数据库自动创建在 `cloud/turbine.db`；`cloud/.env` 不存在时用代码默认值（见 §3.5）。

### 1.3 前端（可选）

```bash
cd wind-turbine-diagnosis
npm install
npm run dev       # http://localhost:3000（vite 代理固定指向生产 8.137.96.104:8000，勿改）
npm run build     # 产出 dist/
```

### 1.4 DC24 实机一键链

双击仓库根 `start_dc24.bat`，等价于 `uv run python scripts/dc24_start.py`：
首次运行由 uv 自动完成环境创建与依赖同步，然后一键启动本机后端 + 已构建前端 + 真实硬件边端。
细节见 [DC24 采集说明](DC24_ACQUISITION.md)。

## 三、ECS 全新部署

生产环境：IP `8.137.96.104`，systemd 服务 `CNN.service`，部署路径 `/opt/CNN`，一键部署 `bash /opt/CNN/deploy.sh`。

### 3.1 购买与连接

1. [阿里云控制台](https://ecs.console.aliyun.com/) 创建实例：Ubuntu 22.04 LTS、**2核2G**（现役规格，内存红线见总则）、40G 系统盘。
2. 记录 **root 密码** 与 **公网 IP**，安全组放行 22/80/8000。
3. SSH 登录：`ssh root@你的公网IP`，然后更新系统并装基础工具：

   ```bash
   apt update && apt upgrade -y
   apt install -y git curl nginx
   systemctl enable --now nginx
   ```

   Node.js（服务器上构建前端用）：

   ```bash
   curl -fsSL https://deb.nodesource.com/setup_18.x | bash -
   apt install -y nodejs
   ```

   > 不需要安装系统 Python / pip / venv——Python 3.13 由 uv 托管下载（ADR-0001）。

### 3.2 安装 uv

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
source ~/.bashrc    # 让 /root/.local/bin 进 PATH
uv --version
```

> `deploy.sh` 也会在检测不到 uv 时自动执行同样安装，此步可省，但建议先装好便于排错。

### 3.3 获取代码

```bash
git clone https://github.com/lx827/CNN.git /opt/CNN
```

### 3.4 安装依赖（uv sync --frozen）

```bash
cd /opt/CNN
uv sync --frozen    # 严格按 uv.lock 安装,Python 3.13 由 uv 自动下载
```

### 3.5 配置 `cloud/.env`

```bash
nano /opt/CNN/cloud/.env
```

生产必改键（`.env` 不入库，需手动创建；其余键与默认值以 `cloud/app/core/config.py` 为准）：

```env
API_HOST=0.0.0.0
API_PORT=8000
USE_SQLITE=true
ADMIN_PASSWORD=改成强密码          # 网页登录密码
SECRET_KEY=改成长随机串            # JWT 签名密钥
EDGE_API_KEY=边端与云端一致的长随机串
```

已有部署也要检查这三个键是否齐全。`deploy.sh` 不生成或覆盖未入库的 `cloud/.env`,旧文件缺键时应用仍会使用源码默认值;重新部署代码不会自动补齐。

网页密码与 JWT 密钥应分别独立生成,可在 `cloud/` 目录运行 `uv run python -c "import secrets; print(secrets.token_urlsafe(24)); print(secrets.token_hex(48))"`,将两行结果分别写入 `ADMIN_PASSWORD` 与 `SECRET_KEY`,不要提交或粘贴到公开日志。限制文件权限为 `chmod 600 /opt/CNN/cloud/.env`（现役服务以 root 运行）,修改前将备份放在仓库外的私密目录。已有有效 `EDGE_API_KEY` 应保留;轮换时必须同步边端,值使用随机 ASCII 字符串。

保存后执行 `systemctl restart CNN`,验证新密码可登录、默认密码被拒绝,再用登录返回的 JWT 访问受保护接口。更换 `SECRET_KEY` 后已有网页登录令牌失效,用户需重新登录。网页当前只要求访问密码,无用户名输入;登录页写死的默认密码提示不代表生产实际配置。

可选键（按需添加）：

```env
# 跨域白名单(逗号分隔;默认含 localhost:3000/4173、8.137.96.104 与 null,
# 前端换域名/端口访问时需把新源加进来,否则浏览器跨域请求被拒)
CORS_ORIGINS=http://你的域名,http://localhost:3000
# DC24 采集任务落盘根目录(默认 <仓库根>/data/acquisitions,即 /opt/CNN/data/acquisitions;需放到数据盘时修改)
ACQUISITION_DATA_DIR=/opt/CNN/data/acquisitions
```

> `ANALYZE_INTERVAL_SECONDS` 是代码常量（`config.py` 内 30 秒），不是 `.env` 键，改间隔需改代码。

### 3.6 安装 systemd 服务

服务单元模板在仓库内：`deploy/cloud/CNN.service`（`deploy.sh` 会自动安装/更新它）。
手动安装：

```bash
cp /opt/CNN/deploy/cloud/CNN.service /etc/systemd/system/CNN.service
systemctl daemon-reload
systemctl enable --now CNN
systemctl status CNN --no-pager
```

单元要点（模板全文见上文件）：

```ini
[Service]
Type=simple
User=root
WorkingDirectory=/opt/CNN/cloud
ExecStart=/opt/CNN/.venv/bin/python -m uvicorn app.main:app --host 0.0.0.0 --port 8000
Restart=always
RestartSec=5
```

- ExecStart 直指 uv workspace 产出的 `/opt/CNN/.venv/bin/python`，服务运行不依赖 uv 命令与 PATH。
- `WorkingDirectory` 必须是 `/opt/CNN/cloud`：`app.main` 模块路径与 SQLite 相对路径（`turbine.db`）都以它为基准。
- 验证：浏览器访问 `http://你的公网IP:8000/docs`，能看到 API 文档页面。

> **旧环境清理**：从 venv/pip 时代迁移过来的机器，确认新服务正常后可删除遗留的
> `/opt/CNN/cloud/venv`（uv 环境在仓库根 `.venv`，与它无关）。

### 3.7 配置 Nginx 反向代理

```bash
nano /etc/nginx/sites-available/cnn
```

```nginx
server {
    listen 80;
    server_name 你的公网IP;    # 有域名填域名

    # 后端 API 代理
    location /api/ {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }

    # WebSocket 代理
    location /ws/ {
        proxy_pass http://127.0.0.1:8000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
    }

    # 前端静态文件(首次需本地 npm run build 后上传 dist/,日常更新由 deploy.sh 在服务器构建)
    location / {
        root /opt/CNN/wind-turbine-diagnosis/dist;
        index index.html;
        try_files $uri $uri/ /index.html;
    }
}
```

```bash
ln -s /etc/nginx/sites-available/cnn /etc/nginx/sites-enabled/
nginx -t && systemctl reload nginx
```

验证：浏览器访问 `http://你的公网IP`，看到前端页面。

## 四、日常更新（一键部署）

### 4.1 完整部署

在服务器上：

```bash
bash /opt/CNN/deploy.sh
```

脚本依次执行（任一步失败即中止，不会带病重启服务）：

1. uv 引导：检测不到 uv 时用官方脚本安装；
2. `git switch main && git pull --ff-only` 同步代码；
3. `uv sync --frozen` 按锁文件更新依赖；
4. 安装/更新 `CNN.service`（与模板不一致时先备份旧单元再覆盖）；
5. `systemctl restart CNN` 重启后端；
6. `npm run build` 构建前端（可跳过，见下）；
7. 显示服务状态。

### 4.2 只更新后端（跳过前端构建）

```bash
bash /opt/CNN/deploy.sh -s        # 或 --skip-frontend
```

### 4.3 演练 / 核对（dry-run，零改动）

```bash
bash /opt/CNN/deploy.sh --dry-run     # 只打印将要执行的每一步,不执行
```

本地 WSL 克隆也可演练服务器流程：

```bash
cd ~/code/CNN
git fetch origin && git checkout <分支>
CNN_DEPLOY_ROOT=$PWD bash deploy.sh --dry-run
git checkout -      # 演练完切回原分支
```

## 五、可选：切换 MySQL 数据库

`pymysql`、`cryptography` 已在 workspace 依赖内（`cloud/pyproject.toml`），**无需再安装任何包**。

1. 安装并初始化 MySQL：`apt install -y mysql-server && systemctl enable --now mysql`
2. 建库授权（同旧流程）：

   ```sql
   CREATE DATABASE turbine_db CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
   CREATE USER 'turbine'@'%' IDENTIFIED BY 'turbine1234';
   GRANT ALL PRIVILEGES ON turbine_db.* TO 'turbine'@'%';
   FLUSH PRIVILEGES;
   ```

3. 修改 `cloud/.env`：

   ```env
   USE_SQLITE=false
   DB_HOST=127.0.0.1
   DB_PORT=3306
   DB_USER=turbine
   DB_PASSWORD=turbine1234
   DB_NAME=turbine_db
   ```

4. 重启生效：`systemctl restart CNN`（依赖未变，不需要 uv sync）。

## 九、常见问题

### Q1: 后端启动失败

```bash
journalctl -u CNN -n 50 --no-pager
# 常见原因:
# - 端口被占用:lsof -i:8000
# - 依赖未装/锁文件变动:cd /opt/CNN && uv sync --frozen
# - cloud/.env 配置错误(键名以 cloud/app/core/config.py 为准)
```

### Q2: 前端白屏

- `tail -f /var/log/nginx/error.log`
- 确认 `wind-turbine-diagnosis/dist/` 存在（首次需构建）
- 浏览器 F12 → Network 查看接口是否通

### Q3: uv 官方脚本下载慢/失败（国内网络）

手动安装后重试 `deploy.sh`：

```bash
# 方式一:GitHub release 直接下载 uv 二进制
curl -LsSf https://github.com/astral-sh/uv/releases/latest/download/uv-x86_64-unknown-linux-gnu.tar.gz | tar xz -C /usr/local/bin --strip-components=1
# 方式二:pipx/pip 装到独立工具环境(仅作为 uv 本体的引导手段,项目依赖仍只经 uv sync)
```

### Q4: 内存不足（2G 红线）

```bash
free -h           # 先确认是应用内存还是磁盘/缓存问题
# 不要试图增加线程池或并发参数(AGENTS.md §5)
# 必要时加 Swap:
fallocate -l 2G /swapfile && chmod 600 /swapfile && mkswap /swapfile && swapon /swapfile
```

### Q5: 数据库文件

SQLite 文件在 `/opt/CNN/cloud/turbine.db`。备份：

```bash
cp /opt/CNN/cloud/turbine.db /backup/turbine_$(date +%Y%m%d).db
```
