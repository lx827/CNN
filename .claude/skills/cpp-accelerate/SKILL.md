# C++ 加速算法开发规则

目标：算法按数学能力独立组合，内部 C++ 接口专门服务加速；公开 C++ 与 Python 包装共用入口，全部入口复用同一计算实现。

## 开始工作

先读仓库 `AGENTS.md`、相关算法族契约和本次任务规格；构建与当前实现见 [计算库说明](../../../docs/native_compute.md)，架构取舍见 [ADR 0007](../../../docs/adr/0007-native-algorithm-module-interfaces.md)。本 skill 定义目标规则，不表示现有源码已完成迁移。

明确本次改变的算法范围和验收结果。加速移植保持原数学语义；变更公式、边界、随机序列或质量状态需作为独立决定处理。读源码确认现有行为，不从算法名称推断兼容。

使用外部 Python 参考时，先确认包名、导入模块、版本和实际源码路径。同属 EMD 的 `emd.sift` 和 `emd-signal/PyEMD` 具有不同公式，不能互相代替。直接使用所选参考，不额外建立源码 hash 校验或参考清单 JSON。

实施前画出模块依赖和数据所有权：谁拥有输入、输出、临时空间，哪些步骤需要可写副本，哪些中间结果可复用。沿完整调用链检查分配和隐式复制，不能只看入口是否用了 `span`。

## 按数学能力组织模块

- `lib/core/` 承载跨模块通用的基础结构与底层约定，例如数组、view、缓冲区。算法专用参数、结果和工作区归所属模块。构建信息等非算法基础设施可以留在 core。
- 插值、线性求解、变换、包络、EMD 等算法按独立数学能力组织；相关能力按算法族归目录，小模块可以先使用一对头文件和源文件。
- 可独立定义数学契约且有明确复用价值的能力可以直接建模块，不要求已经存在第二个调用者。专用小步骤留在所属模块，不因“可能复用”机械拆分每个函数。
- 算法模块允许组合依赖，依赖图保持无环；core 不反向依赖算法。可复用算法仍是算法模块，不因多个调用者就归入 core。
- 模块边界、文件边界和 CMake target 边界分别判断。一个目录可以容纳多个相关算法；不要求每个函数、文件或入口单独建立 target。
- 头文件只暴露调用契约。模块间通过约定的执行接口调用，不跨模块包含私有实现头或复制算法公式。

目录按职责取名，不规定所有模块必须有同一套文件。`api.hpp` / `execution.hpp` 是可选命名；小模块可以在同一头文件中清晰区分两类入口。

## 两类 C++ 入口，一个计算实现

| 入口 | 调用者 | 职责 |
|------|--------|------|
| 公开接口 | 外部 C++；Python 薄绑定 | 易用的参数与拥有型结果，明确错误和生命周期，准备输出与工作区后调用内部执行接口 |
| 内部执行接口 | 本模块公开入口；其他算法模块 | 为高效组合单独设计：借用输入、直接写输出、复用工作区和必要中间结果，使用已建立的前置条件 |

内部执行接口是允许跨算法模块使用的库内契约，不等同于任意 `detail` 私有函数。它可以随源码版本协同修改，不承诺外部 ABI 稳定。外部 C++ 第一版按头文件和 CMake target 源码集成，允许重新编译。

公开入口不复制计算公式；Python 也不另建一套算法。绑定调用公开 C++ 入口；若数据所有权或布局适配确有需要，可以加纯 C++ 辅助入口，但仍复用同一内部执行路径。

### 内部接口为加速而设计

- 常见形状为只读输入 view、可写输出 view、参数以及 `Workspace&`；按真实算法设计，不强制统一函数签名或万能基类。
- 在执行前建立形状、容量、节点顺序等前提，热循环沿用这些前提。公开 C++ 层负责算法参数与数据前提；绑定负责 Python 类型、维度和布局，安排好检查归属，避免重复全数组扫描。
- 输出直接写入调用者指定的存储。支持原地或输入输出重叠时，明确允许的重叠方式；其余路径由调用者保证不重叠。
- 对已知输入规模准备容量，同规模重复计算复用已准备的缓冲区。动态增长明确发生阶段与成本，不把每轮重新分配藏在辅助函数中。
- 允许复用预计算结果、使用中间结果 view、融合计算和省略无需返回的中间数组。中间 view 的失效点写在头文件中。
- 融合发生在模块提供的执行能力内。上层不绕过接口重写下层算法；融合改变舍入或归约次序时按数值契约验证。
- “接近零开销”指减少接口额外的复制、分配、重复检查和不必要动态派发，不保证计算本身零成本或编译器必然内联。按数据路径和测量证明收益。

## 所有权与内存交接

**输入借用。** 连续输入通过只读 view 使用，owner 至少存活到同步调用结束。输入 view 不逃逸到调用之后。为算法状态更新需要的可写副本应明确保留，区分必要工作副本与传参复制。

**输出独立。** 公开结果用 RAII 拥有存储，优先移动交接；下一次执行、工作区销毁或复用不能覆盖已返回的结果。内部输出由调用者提供；只有显式的借用接口才返回工作区 view，并说明何时失效。

**临时空间复用。** Workspace 拥有可写临时缓冲区，调用者可以跨筛分、模态或连续任务复用它。每个活跃调用独占工作区；嵌套调用使用不冲突的子工作区。发生异常或算法失败后，说明它是否仍可复用。

**最终结果交接。** 不能把工作区指针直接包装成永久结果。可以转移一块独立缓冲区的 owner，也可以直接写入最终拥有者提供的存储；若转移了工作区缓冲区，后续重建容量的成本须计入。

**Python 交接。** NumPy dtype、布局转换和 capsule/GIL 操作留在 `bind/` 或 Python 适配层。合规输入借用；需要转换时在边界集中完成并计入成本。最终 C++ 结果的 owner 由 NumPy 持有，最后一个相关数组/view 释放时才销毁。释放动作与原分配器配套；异常路径也保持 RAII。

**隐式复制审查。** 检查 view/Map 到拥有型数组的物化、表达式临时值、按值参数、容器扩容和输出转交。移动对象不等于必然没有重新分配，`span` 参数也不保证函数内部无复制。

每个接口在源码注明：输入输出形状、可变性、别名限制、owner、借用有效期、容量准备、可能分配的位置和状态含义。Markdown 不维护第二份真实函数签名。

## 可移植 SIMD 与数值路径

适合连续批量计算的路径优先使用 Eigen 等可移植数值基座的数组表达式、SIMD 和融合运算，将底层指令选择交给其支持的目标后端。区分 SIMD 向量化与线程并行；启用 SIMD 不增加线程额度。若使用专有 intrinsic，将其隔离到明确的 ISA 实现并保留可运行的基线路径。

逐项识别均值/更新、乘除、系数构造和求值等批量路径，以及带依赖链的求解、分支压缩、查找等专用流程。根据依赖和测量选择实现，不强迫递推算法全部向量化。数值敏感的归约顺序可以保留，明确其成本；不能为向量化擅自改变停止判据或打开 fast-math。

跨平台与跨 CPU 架构分别验证：Windows/Linux 可移植不等于 x64/ARM64 已验证。记录目标架构、编译器、选项、实际启用 ISA 与数值/性能证据；使用编译器向量化报告、反汇编或相应内核证据确认热点实际向量化。仅链接 Eigen 或 build_info 列出 ISA 不足以证明每条算法路径向量化。

按源码配置识别当前支持矩阵。固定 ISA 产物只部署到支持它的 CPU，构建缓存区分目标；未经独立设计不引入全库运行时多 ISA 派发。把数值基座的理论支持、实际构建成功和已完成的目标资源验收分别报告，未验证架构不标为已支持。

## 对象与并发

默认用函数表达计算、值对象表达参数和结果。需要保存临时容量时使用 Workspace；需要预计算或后端资源时使用 Plan。用状态的生命周期决定对象边界，不为内存管理建立继承式算法框架。

线程和任务由上层统一调度。算法不自行创建线程池，也不使用全局可写工作区。不同并发任务各自拥有工作区；同一工作区只在前一个调用结束后复用。线程本地存储不是隐式默认，因为嵌套调用也可能冲突。

只读配置和不可变预计算数据可共享，Plan 是否可并发执行须遵守其数值后端契约。后端有内部线程时显式约束，避免上层任务并行与后端并行叠加。

峰值内存按输入长度、模态数、集成次数及活跃任务数一起计算，分别列输入、结果、工作区和缓存。不要笼统要求所有算法 `O(N)`；例如 CEEMDAN 噪声模态可能同时依赖多个规模维度。生产并发额度遵守仓库 2C2G 约束。

## 算法状态

算法结果保留极值不足、未收敛、数值失败等有实际意义的状态，以及相应迭代信息和有效输出范围。状态设计以本算法为准，不先建立包罗所有算法的全局枚举或 `Result` 框架。

违反公开接口前置条件可以抛异常；已知前提成立的内部热路径不重复防御性扫描。算法自身的正常失败或不可判定不能被吞掉，也不能用默认值、空数组或成功标志伪装。异常是否会发生如实声明，不为速度一律添加 `noexcept`。

## 组合案例

设计分解算法、包络或变换的复用与融合时，读 [EMD 与 Hilbert 示例](references/composition.md)。示例表达目标结构与调用原则，不声称已经存在对应目录或接口。

## 验证与完成

沿真实调用接口验证数学结果和状态，按风险选择必要检查：公开入口与内部执行路径一致、输入保留、输出生命周期、工作区重复使用及规模变化、允许的别名方式、并发调用隔离和失败传播。

检查完整调用链的分配/复制，适合时对准备后重复执行记录分配次数；性能同时看端到端耗时和真实峰值内存，记录输入准备与必要副本，不凭类名、view、Eigen 或 SIMD 选项宣布加速完成。

数值敏感算法使用事前冻结的误差与元数据契约。保持现有构建与目标 ISA 约束；测试选择、P0 触发条件和工具链以仓库规则及 [测试索引](../../../docs/tests/INDEX.md) 为准，完成必要验证后不重复扩大测试。

交付包含实际变更、调用与所有权说明、已执行验证和限制。文档区分目标规则与已实现状态。使用本 skill 不意味着默认切换生产后端、迁移全库或新增算法变体。
