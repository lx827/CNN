# 算法组合与内部加速示例

以下为设计示例，目录名和入口名不构成现行 API。

## 模块归属

```text
lib/
├─ core/                 # 通用数组、view、基础结构
├─ interpolation/        # PCHIP、cubic
├─ solvers/              # 带状求解等独立数值能力
├─ transforms/           # FFT、希尔伯特变换、解析信号
├─ envelope/             # 极值插值包络、Hilbert 包络
└─ emd/                  # 筛分、停止、模态与集成编排
bind/                    # Python 类型、布局、GIL、owner 转换
```

小模块不必立刻拥有独立目录或 CMake target。基础结构按广泛共享性归 core；`InterpolationWorkspace`、包络参数等归所属算法模块。依赖方向示例：EMD → 极值插值包络 → 插值 → 求解器；Hilbert 包络 → 解析信号 → FFT。所有模块可使用 core，core 不依赖算法。

## EMD：包络独立，筛分组合

极值插值包络是可独立使用的能力，不应因为 EMD 是当前唯一调用者就只能藏在 EMD 私有实现中。其数学契约包含极值定位/精化、端点镜像、插值方式、外推和节点不足状态；EMD 决定如何使用上下包络进行信号更新、停止和模态提取。

公开包络入口准备独立上下包络结果和工作区，然后调用内部执行入口。EMD 的筛分入口则准备可复用的上下包络存储和子工作区，直接调用包络内部执行入口。

```text
EMD 持有：当前筛分信号、更新缓冲区、上下包络、包络子工作区
  每轮：
    包络执行接口 → 直接写入上下包络
      插值执行接口 → 复用系数/求解缓冲区
    计算信号更新和停止状态
    交换当前/更新缓冲区
```

这样内部执行接口具有真实的性能职责：不必为了模块化，每轮构造新的公开包络结果和插值临时 owner。准备容量时考虑节点数变化、镜像增长和对齐，不把“输入长度相同”误当成“全部临时形状相同”。

插值模块自己管理节点、系数和求值的契约。EMD 不直接访问插值私有缓冲区；需要复用的中间结果由插值执行接口以明确生命周期的 view 或预计算对象提供。

## Hilbert 包络：数学分层，执行可融合

对于实信号 x，希尔伯特变换是实信号 H(x)，解析信号是复信号 z = x + iH(x)，Hilbert 包络为 |z|。有的数值库将返回解析信号的入口也命名为 hilbert，选后端时先核实其真实契约。

解析信号的 FFT 路径对频谱施加解析信号乘子：保留 DC，正频加倍，负频清零；偶数长度还保留 Nyquist。奇偶长度、归一化、轴、补零和边界行为按采用的算法契约处理。

```text
公开解析信号入口：输入 → 内部解析信号执行 → 独立复数结果
公开 Hilbert 包络入口：输入 → 内部包络执行 → 独立实数结果
内部包络执行：
  复用 FFT/复数工作区完成解析信号
  从工作区复数数据直接求幅值，写入调用者输出
```

调用者只要包络时，无须先调用公开解析信号入口分配独立复数结果，也无须额外生成一个 H(x) 实数组再拼接复数数组。底层 FFT 后端仍可能需要独立输入输出缓冲区，其真实成本必须保留。

同一流程同时需要包络和相位时，可以复用解析信号，但由其接口说明存储 owner 和有效期。融合与中间结果复用均通过模块能力表达，不由包络模块重写 FFT。

Hilbert 包络和极值插值包络归同一算法族目录，不代表它们必须实现同一种输出接口：前者通常输出一个幅值数组，后者输出上下两条曲线。

## 完整 EMD 家族移植的后续决定

本规则可以指导完整 EMD/EEMD/CEEMDAN 的实现，但不替代具体移植规格。开始该任务时仍需决定：

- 原生范围是否仅覆盖现有三种分解与四种筛分组合，是否保持当前随机噪声来源与顺序。
- NumPy 继续生成噪声后批量交给 C++，还是另行制定原生随机数契约；相同 seed 不保证不同生成器产生相同序列。
- EEMD 聚合和 CEEMDAN 噪声模态缓存的存储、归约次序与资源预算。
- 可变模态数的输出容量、有效长度和最终 owner 如何交接。

这些属于具体算法迁移设计，不能从“内部接口为了加速”推导出擅自改变公式、随机性、聚合顺序或并发数的许可。
